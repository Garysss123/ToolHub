JSON 與 XML 轉換常見問題

關於 JSON 轉 XML、資料格式轉換、SOAP 與 REST API 的熱門疑問

雖然 JSON 已成為現代 Web API 的主流格式，但仍有許多場景需要使用 XML：

  • SOAP Web Services：企業級 API（金融、醫療、政府系統）通常僅支援 XML 格式，需將 JSON 資料轉為 SOAP XML 請求。
  • Legacy System 整合：老舊系統（Mainframe、AS/400、Java EE）往往只接受 XML 輸入。
  • Sitemap XML 提交：提交網站地圖給 Google、Bing 等搜尋引擎時需要標準 XML 格式。
  • Java / C# 生態系：許多 Java（JAXB）與 C#（XmlSerializer）系統使用 XML 作為設定與資料交換格式。
  • RSS Feed 發布：部落格、Podcast 等內容發布格式使用 XML。
  • 文檔格式：SVG 向量圖形、Office Open XML（docx/xlsx）內部使用 XML 結構。

簡單來說：前端/行動端用 JSON 處理資料，後端/企業系統用 XML 交換資料 — 本工具正是兩者之間的橋樑。

JSON 與 XML 都是結構化資料格式，但在設計理念上存在根本差異：

特性 JSON XML
可讀性 簡潔輕量，易讀 標籤繁多，較冗長
型別支援 原生：字串、數字、布林、Null、陣列 純文字，需 Schema（XSD）定義型別
中繼資料 ❌ 無 Attribute ✅ 內建 Attribute 機制
Namespace ❌ 不支援 ✅ 支援 xmlns
註解 ❌ 不支援 ✅ <!-- -->
解析速度 極快（原生支援） 較慢（需解析標籤）
檔案體積 較小 較大（重複標籤）

選擇建議：現代 Web API、前後端通訊、行動應用 → 優先用 JSON。企業系統、文件交換、需要 Schema 驗證 → 選擇 XML。

SOAP（Simple Object Access Protocol）是一種嚴謹的 XML 基礎通訊協定，由 Microsoft 於 1998 年提出。SOAP 訊息必須使用 XML 格式，並遵循嚴格結構（Envelope → Header → Body）。

REST（Representational State Transfer）是 Roy Fielding 於 2000 年提出的輕量級 API 設計風格，通常使用 JSON，但也支援 XML 格式。

SOAP 特性

  • 嚴格的 WSDL 定義
  • 內建安全規範（WS-Security）
  • 有狀態 / 無狀態皆可
  • 僅支援 XML 格式
  • 企業級應用、金融系統

REST 特性

  • 資源導向設計（URI）
  • 無狀態（Stateless）
  • 支援 JSON / XML / 純文字
  • 使用標準 HTTP 方法
  • 現代 Web 與行動應用

本工具特別適合將 REST API 的 JSON 回應轉換為 SOAP XML 請求，協助企業系統現代化遷移。

  • Root：指定最外層的 XML 根元素名稱（預設為 "root"）
  • Item：指定每個陣列元素的包裹標籤名稱（預設為 "item"）

由於 XML 沒有原生資料型別系統（所有內容皆為文字節點），轉換規則如下：

  • 字串（String）：直接輸出為 XML 文字內容，特殊字符自動轉義：
    & → &amp;、< → &lt;、> → &gt;
  • 數字（Number）：轉為字串輸出，如 123.45 → <price>123.45</price>
  • 布林（Boolean）：轉為 true 或 false 字串
  • Null：輸出為自閉合標籤，如 <value/>
  • 空物件/陣列：輸出為自閉合標籤

範例：

JSON: {"name": "Tom", "age": 30, "active": true, "data": null}
XML:  <root>
        <name>Tom</name>
        <age>30</age>
        <active>true</active>
        <data/>
      </root>

XML Declaration（XML 宣告）是 XML 文件開頭的處理指令，用於指定 XML 版本與編碼方式：

<?xml version="1.0" encoding="UTF-8"?>

何時開啟：

  • 建議開啟：當 XML 用於正式文件交換、SOAP API、Sitemap 提交、RSS Feed 發布時
  • 可關閉：當 XML 內容僅為內部使用、片段嵌入（XML Fragment）、或目標系統不要求宣告時

本工具預設開啟 XML Declaration，編碼固定為 UTF-8，確保最佳相容性。

從 JSON 到 XML：跨平台資料交換的完美橋樑 — 完整實戰指南

在現代軟體開發中，JSON（JavaScript Object Notation）與 XML（eXtensible Markup Language）分別代表了兩種不同時代與不同場景的資料交換標準。掌握兩者之間的轉換，不僅是技術必備技能，更是企業系統整合（EAI）、API 設計與 Legacy 系統現代化過程中的關鍵能力。

什麼是 JSON？

JSON（JavaScript Object Notation）由 Douglas Crockford 於 2001 年規範化，是一種輕量級的資料交換格式。JSON 源自 JavaScript 語法的子集，使用鍵值對（Key-Value Pairs）與陣列（Arrays）組織資料，語法簡潔、解析效率極高。

JSON 的設計哲學是「簡潔而高效」。沒有結束標籤、沒有 Attribute、沒有 Namespace — 這種極簡設計使其在 Web 開發中迅速普及。JSON 的主要優勢領域包括：

  • RESTful API — 現代 Web API 的首選資料格式
  • NoSQL 資料庫 — MongoDB、CouchDB 等使用 JSON-like 文件儲存
  • 前端開發 — React、Vue、Angular 等框架原生處理 JSON
  • 設定檔 — package.json、tsconfig.json、.eslintrc.json 等
  • 即時通訊 — WebSocket 訊息交換格式

什麼是 XML？

XML（可擴展標記語言）由 W3C 於 1998 年制定，是一種可擴展的標記語言，設計目標是「既被人類閱讀，也被機器解析」。XML 使用自定義標籤（Tags）來描述資料結構，並支援 Attribute（屬性）、Namespace（命名空間）、Schema（XSD） 等豐富功能。

XML 的設計哲學是「嚴格而完整」。每個 XML 文件必須有一個根元素，所有標籤必須正確關閉，Attribute 值必須使用引號。這種嚴謹性使其非常適合需要高度結構化與驗證的場景。主要應用領域包括：

  • SOAP Web Services — 企業級 API 通訊協定
  • Sitemap XML — 搜尋引擎網站地圖標準
  • RSS / Atom Feed — 內容訂閱格式
  • SVG — 可縮放向量圖形
  • Office 文件 — docx、xlsx 內部使用 XML
  • Java / C# 設定 — Maven POM、Spring XML、App.config

JSON 轉 XML 實戰範例

JSON 輸入

{
  "apiRequest": {
    "header": {
      "apiVersion": "1.0",
      "authToken": "sk-1234-abcd",
      "timestamp": "2024-01-15T10:30:00Z"
    },
    "body": {
      "userId": "USR-001",
      "action": "getDetails",
      "includePrefs": true,
      "tags": ["premium", "vip", "beta"]
    }
  }
}

XML 輸出

<?xml version="1.0" encoding="UTF-8"?>
<root>
  <apiRequest>
    <header>
      <apiVersion>1.0</apiVersion>
      <authToken>sk-1234-abcd</authToken>
      <timestamp>2024-01-15T10:30:00Z</timestamp>
    </header>
    <body>
      <userId>USR-001</userId>
      <action>getDetails</action>
      <includePrefs>true</includePrefs>
      <tags>
        <item>premium</item>
        <item>vip</item>
        <item>beta</item>
      </tags>
    </body>
  </apiRequest>
</root>

可以看到，巢狀物件轉為巢狀 XML 元素，陣列中的每個元素以 <item> 包裹（可自訂 item 名稱），布林值轉為字串。

雖然 JSON 已成為 Web API 的主流，但 XML 在以下領域仍然不可或缺：SOAP 架構的企業系統（金融、保險、醫療）、SEO 領域的 Sitemap XML、內容發布的 RSS Feed、向量圖形的 SVG 標準，以及 Microsoft Office 文件格式。
