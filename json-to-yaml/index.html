關於 JSON、YAML 格式轉換與應用的熱門疑問

JSON 與 YAML 都是輕量級的資料交換格式，但它們在設計哲學與使用場景上有顯著差異：

特性 JSON YAML
可讀性 中等 — 大量括號與引號 優異 — 縮排結構，最少符號
型別支援 字串、數字、布林、Null、陣列、物件 同 JSON + 日期、時間戳、錨點引用
註解支援 ❌ 不支援 ✅ 支援 # 註解
多文件 ❌ 單一文件 ✅ 使用 --- 分隔
生態系統 API、Web、資料庫、JavaScript DevOps、CI/CD、Kubernetes、Ansible

選擇建議：機器間通訊選 JSON（輕量、嚴格、解析快）；人類編輯的設定檔選 YAML（可讀性高、支援註解）。

Docker Compose 選擇 YAML 作為設定檔格式（docker-compose.yml）主要基於以下原因：

  • 可讀性優先：Compose 檔案通常需要團隊成員頻繁閱讀與修改，YAML 的縮排結構比 JSON 的巢狀括號更直觀。
  • 註解支援：YAML 允許在設定檔中加入註解，說明每個服務的用途、環境變數的意義或版本變更紀錄。
  • 多文件支援：單一 YAML 檔案可透過 --- 分隔定義多個設定環境（開發/測試/生產）。
  • 錨點與別名：YAML 的 &anchor 與 *alias 機制可避免重複定義相同配置區塊。

範例：docker compose config 指令會將 Compose 檔案轉換為標準格式，方便除錯。

Kubernetes 採用 YAML 作為主要的資源定義語言（K8s YAML apiVersion: apps/v1），原因包括：

  • 宣告式配置：Kubernetes 的核心哲學是「宣告式管理」— 你描述「想要什麼狀態」，而非「如何達成」。YAML 的結構化格式完美匹配這種宣告式模型。
  • 人類可編輯：Pod、Service、Deployment、ConfigMap 等資源定義通常由開發者與維運人員手動撰寫，YAML 的簡潔語法大幅降低認知負擔。
  • 檔案組合性：多個 K8s 資源可以定義在同一個 YAML 檔案中（以 --- 分隔），也可以拆分為多個檔案進行版本控制。
  • 工具生態：kubectl、helm、kustomize 等工具都深度支援 YAML 格式。

雖然 Kubernetes 也支援 JSON 格式，但 YAML 已成為 K8s 生態系統的通用語言。學習閱讀與撰寫 YAML 是 Kubernetes 使用者的必備技能。

常見的 JSON 錯誤包括：

  • 末尾多餘逗號（Trailing comma）："key": "value", ❌ 最後一個屬性不可有逗號
  • 缺少引號：Key 必須使用雙引號包裹，name ❌ 應為 "name"
  • 多餘逗號：如 [1, 2,] 中的末尾逗號
  • 花括號或方括號不匹配
  • 使用單引號代替雙引號

在 YAML 中，縮排（Indentation）是語法的一部分，用來表示資料的巢狀結構與層級關係。這與 JSON 使用花括號 {} 不同，YAML 完全依賴縮排來組織層次。

關鍵規則：

  • 使用空格縮排（不支援 Tab）
  • 同一層級的元素必須有相同的縮排量
  • 子層級必須比父層級多縮排（至少 1 個空格，通常 2 或 4 個）
  • YAML 不允許 Tab 字符——如果使用了 Tab，解析器會報錯

從 JSON 到 YAML：現代 DevOps 的資料格式必修課

在現代軟體開發與 DevOps 領域，JSON（JavaScript Object Notation）與 YAML（YAML Ain't Markup Language）是兩種最廣泛使用的結構化資料格式。前者統治了 API 通訊與 Web 開發，後者則成為設定檔與基礎設施即代碼（Infrastructure as Code）的標準語言。理解兩者的特性與轉換方式，是每位現代開發者的必備技能。

什麼是 JSON？

JSON 由 Douglas Crockford 於 2001 年標準化，是一種輕量級的資料交換格式。它基於 JavaScript 語法的子集，使用鍵值對（{"key": "value"}）與陣列（[item1, item2]）來組織資料。

JSON 的主要優勢在於簡潔、嚴格、解析效率高。幾乎所有程式語言都內建 JSON 解析器，使其成為 Web API（RESTful API）、資料庫（MongoDB、PostgreSQL JSONB）、即時通訊（WebSocket）與設定檔的通用格式。JSON 的嚴格語法（必須使用雙引號、不允許註解、不允許末尾逗號）確保了跨語言的一致性與可預測性。

什麼是 YAML？

YAML（YAML Ain't Markup Language）於 2001 年首次發布，是一種人類可讀性優先的資料序列化格式。與 JSON 使用括號與引號不同，YAML 使用縮排來表示資料結構，類似 Python 的語法風格。

YAML 的設計目標是「讓複雜的設定檔也能被人輕鬆閱讀與編輯」。它支援 JSON 的所有資料型別，並擴充了註解（#）、日期時間、錨點引用（&/*）、多行字串、多文件（---）等實用功能。這些特性使 YAML 成為 Docker Compose、Kubernetes、Ansible、GitHub Actions、GitLab CI、Home Assistant 等主流 DevOps 工具的設定檔標準。

JSON 與 YAML 的詳細對比

JSON 適用場景

  • Web API 請求和回應
  • 瀏覽器與伺服器資料交換
  • 資料庫儲存（MongoDB, PostgreSQL）
  • 應用程式設定檔（Node.js package.json）
  • 即時資料串流與訊息佇列

YAML 適用場景

  • Docker Compose 多容器部署
  • Kubernetes Pod/Service/Deployment
  • CI/CD 管線（GitHub Actions, GitLab CI）
  • 組態管理（Ansible Playbook, SaltStack）
  • 基礎設施即代碼（Terraform, CloudFormation）

JSON 轉 YAML 實戰範例

JSON 輸入

{
  "apiVersion": "v1",
  "kind": "Service",
  "metadata": {
    "name": "web-app",
    "labels": {
      "app": "frontend"
    }
  },
  "spec": {
    "ports": [{"port": 80}],
    "selector": {
      "app": "frontend"
    }
  }
}

YAML 輸出

apiVersion: v1
kind: Service
metadata:
  name: web-app
  labels:
    app: frontend
spec:
  ports:
    - port: 80
  selector:
    app: frontend

可以看到，相同的資料在 YAML 中顯得更簡潔直觀，沒有括號與引號的視覺干擾。
