Text Compare 文字比較完整指南

深入了解文字比較原理、Diff 演算法與使用場景

什麼是 Text Compare（文字比較）？

Text Compare 是一種用於比對兩段文字差異的工具，能夠快速找出文字之間的相同部分與不同之處。無論是程式碼版本控制、文件修改追蹤、AI 輸出結果比對，還是簡單的內容校對，文字比較工具都能幫助您一目了然地識別變更內容。

相較於人工逐行比對，Text Compare 工具可以自動化辨識新增（Added）、刪除（Deleted）和修改（Modified）的內容，並以不同顏色高亮標示，大幅提升效率與準確性。本工具支援 字元（Character）、單字（Word） 和 行（Line） 三種比較粒度，滿足不同場景的需求。

什麼是 Diff？

Diff（Difference 的縮寫）是指計算兩個文字檔案或內容之間差異的過程與結果。Diff 的輸出通常會顯示哪些行被新增、刪除或修改，是版本控制系統（如 Git）和程式碼審查流程中的核心技術。

一個標準的 Diff 輸出包含以下要素：

  • 新增（Added）：以綠色標示，表示在第二段文字中出現但第一段沒有的內容。
  • 刪除（Deleted）：以紅色標示，表示在第一段文字中存在但在第二段中被移除的內容。
  • 修改（Modified）：以黃色標示，表示內容發生變化但並未被完全新增或刪除。
  • 相同（Equal）：未變化的部分，作為比對的基準上下文。

Git Diff 原理

Git 的 Diff 功能基於 Myers 差異演算法（由 Eugene W. Myers 於 1986 年提出），這是一種能夠在 O(ND) 時間複雜度內找到兩個序列之間最長共同子序列（LCS, Longest Common Subsequence）的演算法。

Myers 演算法的核心思想是在一個 編輯圖（Edit Graph） 中尋找最短路徑：

  • 將兩段文字分別作為二維網格的 X 軸和 Y 軸。
  • 當兩個位置的字符相同時，可以沿對角線移動（不消耗編輯次數）。
  • 演算法的目標是找到一條從原點 (0,0) 到 (N,M) 的路徑，使得對角線移動最多（即共同部分最多）。
  • 這條路徑對應的「非對角線移動」就是所需的編輯操作（新增或刪除）。

Git Diff 的輸出格式也是本工具 Unified Diff 模式的基礎。Unified Diff 以 --- 和 +++ 標示檔案名稱，以 @@ ... @@ 標示變更位置，並以 +（新增）和 -（刪除）前綴標示每一行的變更類型。

什麼情況適合使用文字比較工具？

文字比較工具在以下場景中特別實用：

  • 程式碼版本對比：比較不同版本的源程式碼，快速定位修改點。對於 Code Review 和 Debug 非常有幫助。
  • 設定檔比對：比對前後兩個設定檔（如 JSON、YAML、ini）的差異，避免誤改或遺漏關鍵配置。
  • AI 輸出品質驗證：比較不同 Prompt 下 AI 模型的輸出結果，或對比同一 Prompt 在不同模型中的回應差異，找出最優結果。
  • 文件修訂追蹤：追蹤合約、報告、文章等文件的修改歷史，明確顯示每次編輯的具體內容。
  • 內容抄襲檢測：快速比對兩段文字的相似度，輔助判斷內容是否存在抄襲或未經授權的引用。
  • 資料遷移驗證：在資料庫遷移或格式轉換後，比對轉換前後的資料內容，確保轉換的正確性與完整性。
  • 本地化與翻譯校對：對比原始文本與翻譯文本，檢查是否有段落遺漏、重複或不一致的情況。

相似度（Similarity）是如何計算的？

相似度評分（Similarity Score）是衡量兩段文字相似程度的量化指標，範圍從 0%（完全不同）到 100%（完全相同）。本工具使用以下公式計算：

相似度 = (共同字符數 × 2) ÷ (Text A 長度 + Text B 長度) × 100%

其中「共同字符數」基於 最長共同子序列（LCS） 演算法計算得出。LCS 是指在兩個序列中都出現且保持原始順序的最長子序列。LCS 越長，代表兩段文字的共同部分越多，相似度也就越高。

在行比較模式下，相似度以「行」為單位計算；在字元比較模式下，則以「字符」為單位，提供更精細的相似度評估。

Text Compare 常見問題 FAQ

Q1: 字元、單字、行三種比較模式有什麼區別？

字元比較（Character Compare）：以每個字符為單位進行比對，適合精確找出拼寫差異或微小的文字變動。
單字比較（Word Compare）：以單詞為單位進行比對，適合比對句子或段落層級的差異，如文章修改前後。
行比較（Line Compare）：以每一行文字為單位進行比對，最接近 Git Diff 的行為模式，適合程式碼和結構化文字的版本比對。
建議根據您的使用場景選擇最合適的粒度：需要精確到字母選「字元」，比對文章段落選「單字」，程式碼版本控制選「行」。

Q2: Side-by-Side 和 Unified Diff 兩種檢視模式有什麼不同？

Side-by-Side（左右比對）：將兩段文字並排顯示，左側為 Text A，右側為 Text B，差異行以顏色高亮。這種模式直觀易懂，符合傳統的文字比對使用習慣。
Unified Diff（合併差異）：將兩段文字合併為一個統一檢視，以 - 前綴標示刪除行、+ 前綴標示新增行，並以 @@ 區塊標頭標示變更位置。這是最接近 Git Diff 命令輸出的格式，深受開發者喜愛。
桌面環境建議使用 Side-by-Side 模式，行動裝置上 Unified Diff 模式在窄螢幕上有更好的閱讀體驗。本工具在手機上會自動切換為適合的顯示方式。

Q3: 選項中的「忽略大小寫」「忽略空白」「忽略空行」有什麼作用？

忽略大小寫（Ignore Case）：比較時不區分英文字母的大小寫，會將 "Hello" 和 "hello" 視為相同。適合比對對大小寫不敏感的內容。
忽略空白（Ignore Whitespace）：比較時忽略所有空白字符（空格、Tab 等）的差異。適合比對程式碼，因為縮排風格的差異不影響邏輯。
忽略空行（Ignore Empty Lines）：在比較時不將空行視為有效差異。如果兩段文字僅在空行數量上不同，啟用此選項後將被視為完全相同。
這些選項可以組合使用，幫助您過濾掉不關心的差異，聚焦於實質內容的變化。

Q4: 文字比較的相似度評分（Similarity）代表什麼？

相似度評分是一個 0% 到 100% 的指標，用於量化兩段文字的相似程度。100% 表示兩段文字完全相同，0% 表示沒有任何共同部分。計算基於最長共同子序列（LCS）：
相似度 = (2 × LCS 長度) ÷ (Text A 長度 + Text B 長度) × 100%
一般來說，相似度在 90% 以上表示僅有微小差異；70%~90% 表示有部分修改；低於 70% 則表示有較大幅度的變更。請注意，相似度僅供參考，實際差異仍需透過 Diff 檢視來確認具體變更內容。

Q5: 文字內容會被上傳到伺服器嗎？隱私安全嗎？

完全不會。本工具是純前端應用，所有的文字比對、差異計算和相似度分析都在您的瀏覽器中本地完成，沒有任何資料被傳送到伺服器。您可以放心比較任何機密內容，包括原始碼、商業文件或個人資料。即使離線狀態下，本工具也能正常運作。

Q6: 如何導出差異報告？支援哪些格式？

您可以透過「複製結果」按鈕將 Diff 結果複製到剪貼簿，或透過「下載報告」按鈕將差異報告下載為純文字檔案（.txt）。下載的報告包含完整的 Unified Diff 格式輸出，包含檔案標頭、區塊位置標記和差異行內容，適合保存或與團隊分享。Side-by-Side 模式的差異結果會在複製時自動轉換為易讀的標記格式。
