JSON → XML 変換 FAQ

JSON to XML、data format 変換、SOAP、REST API に関するよくある質問です。

JSON は現代の Web API で主流ですが、現在でも XML が必要になる場面は多くあります。

  • SOAP Web Services： 金融、医療、行政などのエンタープライズ API では XML 形式のみをサポートするケースも多く、JSON データを SOAP XML リクエストへ変換する必要があります。
  • レガシーシステム統合： Mainframe、AS/400、Java EE など古いシステムでは XML input しか受け付けない場合があります。
  • Sitemap XML の送信： Google や Bing へ sitemap を送信する場合は standard XML format が必要です。
  • Java／C# エコシステム： Java（JAXB）や C#（XmlSerializer）を使う多くのシステムでは、XML が設定・データ交換形式として利用されています。
  • RSS Feed 投稿者： ブログやポッドキャストなどのコンテンツ配信形式では XML が使われます。
  • ドキュメント形式： SVG vector graphics と Office Open XML（docx/xlsx）は内部で XML structure を使用します。

簡単に言えば、フロントエンド／モバイルでは JSON でデータを扱い、バックエンド／企業システムでは XML でデータ交換する場面が多く、このツールは両者をつなぐ橋渡しになります。

JSON と XML はどちらも structured data format ですが、design concept には根本的な違いがあります：

機能 JSON XML
可読性 シンプル、軽量で読みやすい タグが多く、内容も長くなっています
対応タイプ ネイティブ：string、number、Boolean、Null、array plain text のため、type 定義には Schema（XSD）が必要です。
メタデータ ❌ Attribute なし ✅ 組み込み Attribute 機構
Namespace ❌ 非対応 ✅ xmlns に対応
注釈 ❌ 非対応 ✅ <!-- -->
解析速度 非常に高速（ネイティブ対応） 低速（タグの解析が必要）
ファイルサイズ より小さい より大きい（重複タグ）

選択の目安：モダン Web API、フロントエンド／バックエンド通信、モバイルアプリなら JSON を優先。企業システム、ファイル交換、Schema 検証が必要なら XML を選択します。

SOAPSOAP（Simple Object Access Protocol）は、Microsoft が 1998 年に提案した XML ベースの厳格な通信プロトコルです。SOAP メッセージは XML 形式で、Envelope → Header → Body という決められた構造に従う必要があります。

RESTREST（Representational State Transfer）は Roy Fielding が 2000 年に提唱した軽量な API 設計スタイルです。通常は JSON を使用しますが、XML 形式にも対応できます。

SOAP の特徴

  • 厳密な WSDL 定義
  • 組み込みセキュリティ仕様（WS-Security）
  • stateful または stateless
  • XML 形式のみ対応
  • エンタープライズ向けアプリケーション、金融システム

REST の特徴

  • リソース指向設計（URI）
  • ステートレス
  • JSON / XML / プレーンテキストに対応
  • 標準 HTTP メソッドを使用します
  • モダンな Web・モバイルアプリケーション

XML にはネイティブなデータ型システムがなく、内容は基本的にテキストノードとして扱われるため、変換ルールは次のとおりです。

  • 文字列： XML のテキスト内容として直接出力し、特殊文字は自動的にエスケープします：
    & → &amp;、< → &lt;、> → &gt;
  • 数値： 文字列出力に変換。例： 123.45 → <price>123.45</price>
  • 真偽値： 変換先 true または false 文字列
  • Null： output は次のような self-closing tag です。 <value/>
  • 空のオブジェクト／配列： 自己終了タグとして出力

例：

JSON: {"name": "Tom", "age": 30, "active": true, "data": null}
XML:  <root>
        <name>Tom</name>
        <age>30</age>
        <active>true</active>
        <data/>
      </root>

JSON から XML へ：cross-platform data exchange の橋渡し — 完全実践ガイド

現代のソフトウェア開発では、JSON（JavaScript Object Notation）を使って XML（eXtensible Markup Language）は、それぞれ異なる時代・用途を代表するデータ交換標準です。両者の変換を身につけることは基本的な技術スキルであるだけでなく、企業システム統合（EAI）、API 設計、レガシーシステム刷新においても重要です。

JSON とは何ですか？

JSON（JavaScript Object Notation）は Douglas Crockford により 2001 年に標準化され、軽量なデータ交換形式. JSON は JavaScript syntax の subset から派生しており、キー・バリューペア 付き配列 簡潔な構文でデータを整理でき、非常に効率よく解析できます。

JSON の設計思想は"シンプルで効率的"。終了タグ、属性、名前空間がなく、このシンプルな設計によって Web 開発で急速に普及しました。JSON の主な利点は次のとおりです：

  • RESTful API — modern Web API で推奨される data format
  • NoSQL データベース — MongoDB、CouchDB などは JSON-like な file storage を使います。
  • フロントエンド開発 — React、Vue、Angular などの framework は JSON を native に処理します。
  • Profile — package.json、tsconfig.json、.eslintrc.json など。
  • インスタントメッセージング — WebSocket メッセージ交換形式

XML とは何ですか？

XML（Extensible Markup Language）は 1998 年に W3C によって策定されたExtensible Markup Language、設計目標は「人が読め、機械でも解析できる」ことです。XML はカスタムタグ（Tags）でデータ構造を記述し、次の機能をサポートします Attribute、Namespace、Schema（XSD） その他の豊富な機能。

XML の設計思想は"厳密かつ完全". 各 XML file には root element が必要で、すべての tag を正しく閉じ、attribute value は quote で囲む必要があります。この厳密さにより、高度に構造化され、検証済み シーン。主な適用分野は次のとおりです。

  • SOAP Web サービス — エンタープライズ向け API プロトコル
  • Sitemap XML — 検索エンジン向け Sitemap 標準
  • RSS / Atom Feed — コンテンツ購読形式
  • SVG — スケーラブルベクターグラフィックス
  • Office ファイル — docx、xlsx は内部で XML を使用します
  • Java / C# 設定 — Maven POM、Spring XML、App.config

JSON → XML の実用例

JSON 入力

{
  "apiRequest": {
    "header": {
      "apiVersion": "1.0",
      "authToken": "sk-1234-abcd",
      "timestamp": "2024-01-15T10:30:00Z"
    },
    "body": {
      "userId": "USR-001",
      "action": "getDetails",
      "includePrefs": true,
      "tags": ["premium", "vip", "beta"]
    }
  }
}

XML 出力

<?xml version="1.0" encoding="UTF-8"?>
<root>
  <apiRequest>
    <header>
      <apiVersion>1.0</apiVersion>
      <authToken>sk-1234-abcd</authToken>
      <timestamp>2024-01-15T10:30:00Z</timestamp>
    </header>
    <body>
      <userId>USR-001</userId>
      <action>getDetails</action>
      <includePrefs>true</includePrefs>
      <tags>
        <item>premium</item>
        <item>vip</item>
        <item>beta</item>
      </tags>
    </body>
  </apiRequest>
</root>

As you can see, the nested object is converted into a nested XML element, each element in the array is wrapped with <item> (the item name can be customized), and the Boolean value is converted into a string.

Web API では JSON が主流になりましたが、XML は現在も次の分野で不可欠です。SOAP ベースのエンタープライズシステム（金融、保険、医療）、SEO 用 Sitemap XML、コンテンツ配信用 RSS フィード、ベクターグラフィックス用 SVG 標準、および Microsoft Office ファイル形式。
