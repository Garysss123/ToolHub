HTTP ステータスコードに関するよくある質問と回答

HTTP status codes? Why is it important とは何ですか？

HTTP ステータスコード クライアント（ブラウザー、API client など）からのリクエストに対して、サーバーが返す 3 桁のコードです。インターネット通信の基本的な共通言語として、リクエストの処理結果をクライアントへ伝えます。

ステータスコードは 5 つのカテゴリに分かれます。

  • 1xx（情報） — リクエストを処理中です
  • 2xx（成功） — リクエストは正常に処理されました
  • 3xx（リダイレクト） — リクエストを完了するには追加の操作が必要です。
  • 4xx（クライアントエラー） — リクエストが不正です。client 側で修正する必要があります。
  • 5xx（サーバーエラー） — サーバー側の問題

なぜ重要なのですか？ status code は debugging tool であるだけでなく、次の要素にも直接影響します。 SEO ランキング、ユーザー体験、キャッシュポリシー 付き API 設計. 正しいステータスコードは、信頼できる Web サービスを構築する基礎です。

the difference between 301 and 302 redirects とは何ですか？

301 Moved Permanently リソースが次の状態であることを示します恒久的に移動 新しい URL へ移行します。検索エンジンは旧 URL の SEO 評価（PageRank やリンク評価）を新 URL へ引き継ぎ、インデックスも新 URL へ更新します。

302 Found リソースを表します一時的に移動. 検索エンジンは新しい URL に SEO 評価を引き継がず、古い URL のインデックスを継続します。

主な違い：

  • 301：恒久的な変更で SEO 評価を移転します。Web site renewal、HTTPS migration、URL reconstruction に適しています
  • 302：一時的な変更で SEO 評価は移転しません。A/B test、一時 maintenance page、seasonal promotion に適しています

⚠️ よくある間違い： 多くの Web サイトが恒久リダイレクトに 302 を誤用し、SEO 評価を分散させています。その URL を元へ戻す予定がないことが確実なら、必ず 301。

the difference between 404 and 410 とは何ですか？

404 Not Found リソースを表しますまだ見つかりません、将来復元される可能性があります。最も一般的な error page です。

410 Gone リソースを表します完全に削除されました, redirect はありません。これは 404 より強い signal です。

SEO への影響は大きく異なります：

  • 404: 検索エンジンは一定期間クロールを再試行し、404 が繰り返し確認されるとインデックスから削除します。
  • 410：リソースが恒久的に消失したことを検索エンジンへ明示できるため、URL がインデックスからより早く削除される可能性があります

使用上の推奨事項： content が誤って削除された、または一時的に停止した場合は、 404。product page、old article、discontinued product など、確実に復活させないページであれば次を使用してください 410 検索エンジンのインデックス整理を高速化します。

500 系サーバーエラーをトラブルシューティングするには？

5xx error は server side の問題を示します。代表的な 5xx error の troubleshooting guide：

500 Internal Server Error

最も一般的な server error です。server error log（/var/log/、Nginx/Apache log、application log）で最も一般的な原因は code exception、database connection failure、.htaccess syntax error です。

502 Bad Gateway

プロキシサーバーが upstream から無効な応答を受け取った状態です。Nginx + PHP-FPM 構成でよく見られます。PHP-FPM が起動しているか、Gunicorn や uWSGI など upstream のアプリケーションサーバーが正常動作しているか確認してください。

503 Service Unavailable

サーバーが一時的にリクエストを処理できない状態です。メンテナンス中か、サーバーが過負荷になっていないか確認してください。表示 Retry-After 推定復旧時間を確認するための Header。

504 Gateway Timeout

proxy server が upstream からの response 待ちで timeout しました。nginx を追加 proxy_read_timeout、PHP max_execution_time、または遅いデータベースクエリを最適化します。

一般的なトラブルシューティング手順：① サーバーのエラーログを確認 → ② データベース接続を確認 → ③ メモリと CPU 使用率を確認 → ④ 最近のプログラム配備変更がないか確認 → ⑤ 一時的な問題なら再試行で復旧する場合があります。

HTTP status code は SEO にどのような影響がありますか？

HTTP status code は search engine ranking に直接影響します：

  • 200 OK — 理想的には、検索エンジンが content を通常どおり index できる状態です。
  • 301 Moved Permanently — SEO authority を新しい URL へ滑らかに引き継ぎます。
  • 302 Found — 評価の引き継ぎに失敗すると、score が分散する可能性があります。
  • 304 Not Modified — Crawl Budget を節約
  • 403 Forbidden — content を検索エンジンから access できないようにします。
  • 404 Not Found — 404 が多すぎるとサイト品質評価に悪影響を与えます
  • 410 Gone — 検索エンジンが index をより早く削除します。
  • 429 Too Many Requests — crawler が一時的に crawl を停止する場合があります。
  • 500+ シリーズ — 継続的なサーバーエラーは SEO 順位に深刻な悪影響を与える可能性があります

SEO ベストプラクティス： Web サイトの HTTP status code 分布を定期的に監視し、Google Search Console で 404 や 500 エラーを確認してください。カスタム 404 ページでユーザー体験を改善し、すべてのページが正しい status code を返すことも確認します。

キャッシュ可能な HTTP ステータスコードはどれですか？

HTTP cache policy は status code と密接に関係します。一般的な status code の cache behavior：

  • 200 OK — キャッシュ可能（次に依存 Cache-Control ヘッダー）
  • 203 Non-Authoritative Info — キャッシュ可能
  • 206 Partial Content — キャッシュ可能（分割コンテンツ向け）
  • 301 Moved Permanently — ブラウザーはこのリダイレクトを永久にキャッシュします
  • 304 Not Modified — キャッシュ機構そのものの一部
  • 308 Permanent Redirect — ブラウザーはこのリダイレクトを永久にキャッシュします
  • 302 / 307 — 明示的な指定がある場合のみ Cache-Control 時間キャッシュ
  • 404 — 通常はキャッシュ可能です（ただし推奨されない場合もあります）
  • 410 Gone — 通常はキャッシュ可能
  • 503 Service Unavailable — 設定可能 Retry-After キャッシュと併用

💡 注意： キャッシュ動作を最終的に構成するのは Cache-Control、Expires 付き ETag 同じステータスコードでも、Header 設定によってキャッシュ動作が変わる場合があります。

HTTP ステータスコードとは何ですか？

HTTP ステータスコード インターネット通信を構成する最も基本的で重要な仕組みの 1 つです。ブラウザー、検索エンジンの crawler、API client がサーバーへリクエストを送ると、サーバーは処理結果を示す 3 桁のステータスコードを返します。

これら3つの数値は、それぞれの桁に意味があります：

  • 1xx — 情報レスポンス：リクエストを受信し、処理中であることを示します。
  • 2xx — 成功：リクエストは正常に受信・理解され、受理されました
  • 3xx — リダイレクト：リクエストを完了するには追加の操作が必要です
  • 4xx — Client Error: The request contained bad syntax or could not be 完了
  • 5xx — Server Error：サーバーが有効なリクエストを完了できませんでした。

次のための HTTP ステータスコードの理解 Web 開発、API 設計、SEO 最適化 付き システム管理 すべて必要な基礎知識です。

301 vs 302：リダイレクト戦略の完全比較

Redirect は Web サイト管理でよく使われる技術ですが、 301 付き 302 選択内容によって SEO への影響は大きく異なります。

301 永久リダイレクト

使用 301 この応答は検索エンジンに「この URL は恒久的に移動しました。旧 URL のランキングや評価を新 URL へ引き継いでください」と伝えるものです。これは Web サイト改修、HTTPS migration、URL reconstruction 当時として適切な選択です。

SEO への影響： PageRank の引き継ぎ率は一般に約90〜99%とされ、評価を移行する方法として非常に完全性の高い手段です。Google は旧 URL をインデックスから外し、新 URL を使用するようになります。

302 一時リダイレクト

使用 302 検索エンジンに「この URL は一時的に移動しただけなので、以前の URL のインデックスを維持してください」と伝えるものです。これは A/B テスト、一時メンテナンスページ、季節イベント 当時として適切な選択です。

SEO への影響： 検索エンジンは新しい URL へ評価を引き継がず、古い URL を引き続きインデックスに保持します。

実用的な提案：

  • ✅ HTTP から HTTPS へアップグレード → 301
  • ✅ Web サイトのドメイン名変更 → 301
  • ✅ 複数ページを統合 → 301
  • ⚠️ 短期キャンペーンページ → 302
  • ⚠️ 異なるバージョンを A/B テスト → 302
  • ❌ 恒久リダイレクトに 302 を使用 → SEO 評価を分散させるよくあるミス

404 と 410：コンテンツが存在しない場合のレスポンス選択

ユーザーや検索エンジンが存在しない URL を要求した場合、サーバーは次の応答を返せます 404 Not Found または 410 Gone. 2 つの違いは technical semantics だけでなく、search engine の behavior にも影響します。

404 Not Found

リソースを示す "一時的に「見つかりません。server は resource が再び利用可能になるか把握していません。これは既定の「resource が存在しない」response で、最も一般的な選択です。

  • 適する例：誤削除、一時的な removal、URL spelling error
  • 検索エンジンの挙動：一定期間はクロールを再試行し、404 が複数回続くとインデックスから削除されます

410 Gone

リソースを示す "恒久」が代替 URL を示さずに消失したことを表します。404 よりも明確なシグナルです。

  • 適した用途：discontinued product page、deleted user content、retired API version
  • 検索エンジンの挙動: resource が存在しないことを明示的に伝えるため、URL は index からより早く削除される傾向があります。

SEO アドバイス: 復元しないことが確実なページには、 410 404 の代わりに使うことで、検索エンジンのインデックス整理を早められる場合があります。復旧する可能性が残っているページには標準的な 404 以上です。

500 番台サーバーエラー：診断と修復

5xx error は server-side の問題を表し、SEO と UX にとって最も大きな脅威です。5xx error が長期間続くと、検索エンジンからのサイト信頼度も低下します。

一般的な 5xx エラーと解決策

  • 500 Internal Server Error — 最も一般的なサーバーエラーです。サーバーエラーログ、アプリケーションログ、.htaccess の構文を確認してください
  • 502 Bad Gateway — proxy / gateway が無効な response を受け取りました。Nginx + PHP-FPM、Gunicorn など upstream 構成を確認してください。
  • 503 Service Unavailable — サーバーが一時的にリクエストを処理できません。メンテナンス状況とサーバー負荷を確認し、設定が適切か確認してください。 Retry-After header
  • 504 Gateway Timeout — upstream server の応答が timeout しました。proxy timeout 設定を追加し、database query も最適化してください。

5xx エラーが SEO に与える影響

Google などの検索エンジンは、継続的に 5xx エラーを返すサイトの評価を下げる可能性があります。クローラーが 503 に遭遇した場合は一時的な障害として扱い、後で再試行することがあります。一方、500 や 502 が長期間続くと、サイトの信頼性が低いと判断され、検索順位に悪影響が出る可能性があります。

緊急対応： 大規模な 5xx エラーが発生した場合は、次を設定します 503 ステータスコードと一致 Retry-After header で検索エンジンへ一時的な状態であることを伝えます。crawler に不規則な error を返すより適切です。

HTTP ステータスコードと SEO のベストプラクティス

SEO 業務では HTTP ステータスコードの管理が欠かせません。重要なベストプラクティスは次のとおりです：

ステータスコードの分布を定期的に監視します

使用 Google Search Console Web サイトのステータスコードレポートを定期的に確認してください。特に 404 と 5xx の件数と推移が重要です。404 が大量に発生している場合、サイト構造に問題があるか、多数の外部リンク切れが存在する可能性があります。

リダイレクトを正しく使用

恒久的な変更には 301、一時的な変更には 302 を使います。リダイレクトチェーン（A → B → C）は避け、可能な限り 1 段階で転送してください。リダイレクトループ（A → B → A）も避けます。

カスタム 404 ページ

トップページへのリンクと検索機能を備えた、分かりやすいカスタム 404 ページを提供します。ユーザー体験を改善し、離脱による SEO への悪影響を抑えるのにも役立ちます。

キャッシュを利用してパフォーマンスを改善

正しい設定 Cache-Control 付き ETag header を適切に設定すると 304 Not Modified を活用でき、サーバー負荷を減らし、ページ表示を高速化できます。

サーバーの状態を監視

5xx エラーが大量発生したときにすぐ通知されるよう、サーバー監視の alert を設定してください。CDN を使えば、origin server 障害時に backup page や maintenance page を提供できる場合があります。

概要: HTTP ステータスコードは Web サイトの健全性を示す中核指標です。それぞれのコードを正しく理解して使うことで、開発効率だけでなく SEO とユーザー体験の改善にもつながります。ToolHub の HTTP Status Code Lookup を使えば、任意のステータスコードの詳細説明と推奨対応をいつでも確認できます。
