HTML → Markdown FAQ

HTML から Markdown への変換に関するよくある質問と利用シーンです。

HTML から Markdown への変換は、特に次のような場面で役立ちます：

  • 技術文書の作成: 既存の Web コンテンツを Markdown 形式へ変換し、GitHub README、Wiki、静的サイトジェネレーター（Hugo、Jekyll など）で利用できます。
  • AI プロンプト作成： ChatGPT や Claude などの AI model は Markdown を非常によく理解します。Web content を Markdown へ変換すると、より良い AI response を得やすくなります。
  • コンテンツ移行： blog、CMS、newsletter の HTML content を Markdown へ変換し、別 platform へ移行できます。
  • ナレッジ管理： Web page から抽出した content を Markdown へ変換し、Obsidian、Notion、Logseq などの note tool へ保存できます。
  • 冗長な書式を削除： Word や Google Docs からコピーした内容には不要なスタイルが多く含まれますが、Markdown へ変換する際に自動的に整理できます。

Markdown は「コンテンツ優先」の形式であり、変換時には次の情報が自動的に除外されます。

  • CSS スタイル： color、font、margin、animation などの visual style は保持されません。
  • JavaScript： インタラクティブ動作、イベント処理、動的エフェクトは変換できません。
  • 複雑なレイアウト： multi-column layout、Flexbox、Grid などの layout structure は linear arrangement へ簡略化されます。
  • フォーム要素： 入力欄、ボタン、ドロップダウンなどのフォーム部品は変換できません。
  • 埋め込みマルチメディア： video、audio、iframe などの embedded content は interactivity を失います。

これは欠点というより利点です。Markdown は見た目の装飾ではなく、コンテンツの意味構造に集中するよう促します。

「Clean Markdown」は独自の HTML preprocessing 機能で、特に次の問題を解決します： Word、Google Docs、Evernote また、ChatGPT などの AI ツールから HTML をコピーした際に大量の不要コードが混入する問題にも対応できます。

Clean Markdown は自動的に：

  • すべて削除 <span> および空 <div> ラップ要素
  • 空白や意味のない内容を削除 style、class、id プロパティ
  • Word 固有の MSO 名前空間タグを削除（<o:p>、<!--[if ...]-->）
  • 削除 <font> 空のネストコンテナを持つ label
  • XML の処理命令と CDATA セクションを整理します

有効にすると直接変換よりはるかに整理された Markdown が得られ、利用者から特に評価の高い機能の一つです。

GFM（GitHub Flavored Markdown） 標準 Markdown を基に GitHub が拡張した構文仕様で、現在では事実上の Markdown 業界標準の一つです。GFM では次の機能が追加されています：

  • テーブル： パイプラインを使用 | 構造化された表を作成
  • 取り消し線: 使用 ~~文字~~ 削除を示します
  • タスクリスト： 使用 - [x] および - [ ]
  • コードブロックのシンタックスハイライト: 使用 ```語言 プログラミング言語を指定

HTML と Markdown：構造化マークアップからコンテンツ中心の文章作成へ

Web 技術の発展過程では、HTML（HyperText Markup Language）と Markdown 両者は異なる時代と思想を表しています。HTML は Web の基盤であり、完全なマルチメディア統合とインタラクティブ制御を提供します。一方 Markdown は「フォームより内容を優先「ミニマリズムの精神」。両者の違いと補完関係を理解することは、現代の開発者やコンテンツ制作者にとって重要です。

HTML と Markdown の設計思想の違い

HTML — 精密制御

HTML は表現力の高い markup language です。各要素の色、サイズ、位置、interactive behavior を細かく制御できますが、その代わり構文は複雑で、単純な段落でも <p></p> パッケージ。

Markdown — コンテンツ優先

Markdown は「意味を表す」軽量マークアップです。直感的な記号（#、*、-) で構造を示し、書き手が内容そのものに集中できるようにします。学習コストは非常に低く、10 分ほどで基本を使い始められます。

GitHub Flavored Markdown (GFM) とは何ですか？

GitHub Flavored Markdown（GFM）は GitHub が 2013 年に提案した Markdown 拡張仕様です。標準 Markdown の実務上の不足を補うために、次の機能を追加していますtable、strikethrough、task list、syntax-highlighted code block、auto-link、emoji などに対応します。 などの実用機能があります。現在 GFM は GitLab、Bitbucket、Notion、Discord、Slack など主要なプラットフォームでも広く採用され、クロスプラットフォームで使われる代表的な Markdown 方言の1つになっています。

このツールの「GFM」オプションを有効にすると、変換後の Markdown は GFM 形式のパイプテーブルとタスクリスト構文を使用し、GitHub エコシステムとの互換性を確保します。

Obsidian、Notion、Logseq、Bear などのノートツールは Markdown を中核形式として利用しています。クロスプラットフォームで扱いやすく、将来互換性が高く、バージョン管理にも向いています。

ChatGPT、Claude、Gemini などの AI モデルは Markdown の構造を理解しやすいため、プロンプトを Markdown で整理すると出力品質を大きく改善できる場合があります。
