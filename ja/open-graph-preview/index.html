Open Graph を使った SNS share のベストプラクティス
Open Graph を設定すると、SNS が URL をクロールした際に、明確なタイトル、説明、画像、正規 URL を取得できます。タグがない場合、プラットフォームが本文や任意の画像を自動抽出するため、文の途中で切れたり、重複したり、ブランド表現が不統一になったりすることがあります。X は Twitter Card タグにも対応しているため、OG と Twitter の両方を用意すると、複数プラットフォームで表示内容をより細かく制御できます。
共有画像でよく使われるサイズは 1200 × 630 px（約 1.91:1）です。重要な文字やロゴは、表示レイアウトによって切り取られないよう端から十分に離して配置してください。タイトルや説明文の上限はプラットフォームごとに異なり、完全に共通する厳密な値はありません。このツールは一般的に安全な範囲を示しますが、最終的には各プラットフォームのデバッグツールや実際の投稿で確認する必要があります。
公開前チェックリスト
  1. 各重要ページに、その内容と一致する固有の title と description を設定してください。
  2. absolute HTTPS image URL と明確な canonical URL を使用してください。
  3. image が public access 可能で、server が正しい Content-Type を返しているか確認してください。
  4. 更新後は Platform Debugger で古い cache を削除してください。
よくある質問
Open Graph とは何ですか？
Facebook、LinkedIn、Discord などのサービスが共有カードの内容を理解できるようにする Meta タグのプロトコル群です。
OG 画像の適切なサイズは？
1200 × 630px は一般的な出発点です。重要要素の周囲に safe margin を設け、file size も管理してください。
OG があるのに Twitter Card も必要なのはなぜですか？
X は OG へフォールバックできますが、専用タグを使えば summary_large_image などのカード種別を明示できます。
ツールの preview は実際の platform と完全に同じになりますか？
保証されません。platform 側で UI、device ごとの crop、content policy が更新される可能性があるため、ここでは公開前の概算確認として利用してください。
share card に古い内容が表示されたままの場合、どうすればよいですか？
オンラインの source code が更新されたことを確認してから、Facebook Sharing Debugger や LinkedIn Post Inspector などで再 crawl してください。
