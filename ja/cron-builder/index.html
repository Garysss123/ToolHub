よくある質問（FAQ）

Cron Expression とは何ですか？
Cron Expression は定期タスクの実行時刻を記述する文字列形式で、Linux Crontab、Kubernetes CronJob、GitHub Actions などで広く使われます。標準的な 5 フィールド形式は：

分 時 日 月 星期

各フィールドには数値を指定できます。*（任意）、,（リスト）、-（範囲）、/（ステップ動作）。
5-field Cron と 6-field Cron にはどのような違いがありますか？
標準 Linux Crontab は 5 フィールドを使用します：分 時 日 月 星期. 一部の application（Java Quartz Scheduler など）は 6 column をサポートし、先頭に 秒：秒 分 時 日 月 星期. このツールは Linux Crontab と Kubernetes CronJob で一般的な標準 5 列形式を使用します。
特殊記号 * と - / はそれぞれ何を表しますか？
• * （アスタリスク）："すべて"を意味します。例：毎日、毎時
• , （カンマ）：リスト、例： 1,3,5 1 番目、3 番目、5 番目を表します
• - （マイナス記号）：範囲、例 1-5 1～5 を表します
• / （slash）：step、例： */5 5 単位ごとを意味します
これらの記号は組み合わせて使用できます。例: */15 9-17 * * 1-5 月曜日から金曜日まで、9:00～17:00 の間に 15 分ごとに実行されることを示します。
Linux で Crontab を使うには？
使用 crontab -e 現在の user の Crontab file を編集します。1 行 1 task、形式は：

0 3 * * * /usr/bin/backup.sh

使用 crontab -l 現在のタスクを一覧表示、crontab -r crontab のすべてのタスクを削除します。 % escape が必要な場合は、script を .sh file に書いてから実行することを推奨します。
Kubernetes CronJob の Cron 形式は Linux と同じですか？
基本的には同じです。Kubernetes CronJob も同じ 5-field 形式を使いますが、重要な違いが 1 つあります。Kubernetes は system Localtime ではなく UTC を使い、field では非標準 alias（例： @yearly）。さらに Kubernetes CronJob は次をサポートします timeZone Field でタイムゾーンを指定します（有効化が必要 CronJobTimeZone 関数ゲート）。

Kubernetes CronJob YAML の例：
spec:
  schedule: "0 3 * * *"
  timeZone: "Asia/Taipei"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          name: hello
Cron で日曜日は 0 と 7 のどちらですか？
どちらでも構いません。standard Cron の Day of Week field は 0 または 7 日曜日を示します。一部の実装（Quartz Scheduler など）では 1（月曜日）から 7（日曜日）。このツールは標準的な Linux Crontab の規則に従います：0 日曜日の場合、1-6 月曜日から土曜日まで。
cron スケジュールが正しいか確認するには？
このツールは3種類の verification method を提供します。
• 即時に人間が読める形式へ：生成直後に、人が読める説明テキストを表示します
• 次回実行プレビュー：次の 5 回の実際の実行時刻を表示し、schedule が期待どおりか確認できます。
• 形式の検証：field value が範囲外でないか、special symbol が正しく使われているかを自動確認します。
schedule 作成後は Next Run preview を確認し、実行時刻が正しいことを確認してから deploy してください。

Cron スケジューリングの完全チュートリアル

Cron とは何ですか？

Cron は Linux/Unix の定期実行スケジューラーです。名称はギリシャ語の Chronos（時間）に由来します。Cron はバックグラウンドサービス（daemon）として動作し、設定ファイル（Crontab）に記述した時刻ルールに従って、指定したコマンドやスクリプトを自動実行します。

Cron は Linux のシステム管理以外にも幅広く活用できます：

  • Linux Crontab — system backup、log rotation、system update
  • Kubernetes CronJob — containerized environment 内の scheduled task
  • GitHub Actions — CI/CD パイプラインをスケジュール実行
  • NAS システム — data synchronization、snapshot scheduling
  • データベース保守 — 定期的なバックアップとインデックス再構築
  • 監視アラーム — 定期的なヘルスチェックと指標収集

Cron Expression の field 説明

フィールド範囲説明
分0–591 時間あたりの分数
時0–231 日の時間数
月内の日1–31月内の日
月1–12年内の月
曜日0–7曜日（0,7=日曜、1=月曜…6=土曜）

実用的な使用例

0 3 * * *

データベースのバックアップは毎日午前 3 時に実行されます

*/5 * * * *

5 分ごとに Webサイトのヘルスチェックを実行

0 */6 * * *

6 時間ごとにバックアップサイトへデータを同期

30 4 1 * *

毎月1日の 4:30 に月次レポートを生成します

0 22 * * 5

毎週金曜日 22:00 にリリースをデプロイ

0 0 1 1 *

年間統計は毎年 1 月 1 日にゼロへリセットされます
