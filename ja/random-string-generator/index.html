安全なランダム文字列と Entropy

このツールはブラウザーを使用します crypto.getRandomValues() OS が提供する暗号学的に安全な乱数を取得し、単純な剰余演算による偏りを避けるため rejection sampling を使用します。テスト用識別コード、一時 Token、Nonce、ファイル名、予測困難な文字列の生成に適しています。本番の認証システムで使用する場合は、サーバー側でのライフサイクル管理、ハッシュ保存、権限制御も組み合わせる必要があります。

一般的な繰り返し可能 pattern の理論 entropy はおよそ 長度 × log₂(字元池大小). Unique Character を有効にすると、抽選するたびに利用可能な組み合わせ数が減るため、ツールは 1 文字ずつ選択可能な文字数に基づいて推定します。Entropy は可能性空間の大きさを示す指標であり、特定のシステムにおいてその文字列が必ず安全であることを意味するものではありません。

形式の選び方は？

  • 一般文字列：大文字・小文字、数字、記号、custom character を細かく制御できます。
  • URL Safe：URL fragment 内で安全に使える英数字、hyphen、underscore だけを使用します。
  • Hex：0～9 と a～f のみで構成され、色、Hash 断片、低レベルデータ表現に適しています。
  • 英数字：フォームやコマンドラインでエスケープ問題を起こしやすい記号を避けます。

よくある質問

Math.random() を使用していますか？
いいえ。すべての文字インデックスは Web Crypto API で生成し、rejection sampling によって分布の偏りを抑えています。
Entropy はパスワード強度を保証しますか？
いいえ。これは理論上の可能性を見積もるもので、実際の安全性は保存方法、利用方法、漏えいリスク、攻撃モデルにも左右されます。
unique character の長さに制限があるのはなぜですか？
各 character は 1 回しか使えないため、length は deduplicated character pool size を超えられません。
URL Safe はそのまま URL として使用できますか？
文字列は URL path または query value に適した形式にしてください。ただし完全な URL は、その構成要素に応じて正しく encode する必要があります。
一度に最大何グループまで生成できますか？
極端な入力でページが応答しなくなるのを防ぐため、一度に処理できるのは最大 1,000 グループです。
