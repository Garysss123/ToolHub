よくある質問

Meta Description（メタディスクリプション）は、検索結果に表示されるページ説明文です。直接のランキング要因ではありませんが、適切な Description はクリック率（CTR）を大きく高める可能性があります。推奨の長さは 120〜158 文字程度で、狙うキーワードを含めつつ、自然な CTA（行動喚起）を加えるのが理想です。Description がないページでは、検索エンジンがページ内の関連性の低い文章を自動抽出して概要として表示する場合があります。
Canonical（正規 URL）は、どの URL が「正規版」なのかを検索エンジンへ伝えます。同一ページへ複数の URL からアクセスできる場合の重複コンテンツ問題を防ぎ、SEO 評価を 1 つの URL へ集中させます。Canonical がないと検索エンジン評価が分散し、順位へ影響する可能性があります。
Open Graph（OG）は Facebook が開発した Meta タグのプロトコルで、Web ページを SNS へ共有した際のタイトル、説明、画像、プレビュー表示を制御します。OG タグを適切に設定すると、Facebook、LINE、Slack などでリッチなカード形式のプレビューを表示でき、SNS 共有からのクリック率向上が期待できます。
JSON-LD は、検索エンジンがページ内容をより深く理解するための構造化データ形式です。JSON-LD を実装すると、評価の星、FAQ、パンくずリストなどが Rich Snippets として検索結果に表示される可能性があります。Google も構造化データの実装方式として JSON-LD を推奨しています。
現代の SEO では、Meta Keywords は Google や Bing など主要検索エンジンのランキング要因として使われていません。Google は 2009 年に Keywords Meta タグをランキングに使用しないことを公表しています。Title と Description の品質改善へ注力することをおすすめします。
推奨される Title の長さは 30～60 文字（中国語では約 15～30 文字）です。短すぎる Title ではページ内容を十分に伝えられず、長すぎると検索結果で省略されることがあります。理想的な Title には主要キーワードとブランド名を含め、最も重要な情報を先頭に置きます。
Twitter Card は Twitter / X 上で Web ページのプレビュー表示を制御する専用の Meta タグ仕様です。X はフォールバックとして OG タグも参照しますが、twitter:card、twitter:title、twitter:description、twitter:image を個別に設定すると、X 上でより意図した表示にできます。

SEO 知識百科

SEO Meta Tag の技術的な意味とベストプラクティスを詳しく理解できます。

Title タグのベストプラクティス

Title タグ（<title>) は検索結果でもっとも重要な要素の 1 つで、SEO の基礎です。各ページには固有の Title が必要で、検索エンジンがページの主題を判断する主要な手掛かりになります。

推奨プラクティス：

  • 長さ制御：30〜60 文字（中国語なら約 15〜30 文字）にすると検索結果で切り詰められにくくなります
  • キーワード接頭辞：最重要キーワードを Title の先頭に置く
  • ブランド末尾: Title 末尾にブランド名（例："| ToolHub"）を追加します。
  • 一意: 重複を避けるため、各ページには固有の Title を設定してください
  • true の説明: Title はページ内容を正確に反映し、ユーザーを誤解させない内容にしてください。

Meta Description のベストプラクティス

Meta Description は Google のランキングアルゴリズムに直接使われる要因ではありませんが、検索結果のクリック率（CTR）には大きく影響します。魅力的な description を用意すると、競合の検索結果との差別化につながります。

  • 長さの推奨値：120～158 文字にすると、検索結果で全文が表示されやすくなります
  • キーワードを含む: target keyword を description へ自然に含めると、search engine が keyword を bold 表示する場合があります。
  • 行動喚起: "Learn More"、"Try Now" などの CTA を追加し、クリック意欲を高めます。
  • 一意: すべてのページで同じ Description を使い回さず、各ページ固有の Description を設定してください。
  • 空白を避ける: Description がない場合、検索エンジンがページ本文から自動抽出しますが、多くの場合、表示結果の品質は低下します。

Canonical の用途

Canonical URL は重複コンテンツ問題を解決するための中心的な仕組みです。同じページへ HTTP/HTTPS、www/non-www、末尾スラッシュ、トラッキングパラメーターなど複数 URL からアクセスできる場合、Canonical タグで検索エンジンへどの URL が「正規版」かを伝えます。

実装方法： <head> 参加 <link rel="canonical" href="https://example.com/正確網址/" />. 特に EC site の classification、filter、sort page では、評価分散を防ぐため Canonical が重要です。

Open Graph とは何ですか？

Open Graph（OG）は Facebook が 2010 年に公開した Meta タグプロトコルで、現在では SNS 共有の事実上の業界標準になっています。OG タグを設定すると、Facebook、LINE、LinkedIn、Slack などで Web ページが共有された際のプレビュー表示を細かく制御できます。

必須 OG タグ：

  • og:title — SNS share title（推奨40〜60文字）
  • og:description — ソーシャル共有用説明文
  • og:image — 共有画像（1200×630 px、5 MB 未満を推奨）
  • og:url — ページの標準 URL
  • og:type — ページ種別（website、article など）

JSON-LD 構造化データ入門

JSON-LD（JavaScript Object Notation for Linked Data）は、Google が推奨する構造化データ実装方式です。Web ページに JSON-LD を追加することで、検索エンジンがページ内容をより正確に理解し、検索結果に Rich Snippet を表示できる可能性が高まります。

一般的な Schema タイプ：

  • 組織 — Organization／company 情報（name、logo、social link）。
  • WebSite — Webサイト情報（検索ボックス、サイト名）
  • BreadcrumbList — パンくずリスト（検索結果にパスを表示）
  • FAQPage — よくある質問（詳細 Q&A）
  • 記事 — Article（title、author、publication date）
  • 製品 — 商品（価格、在庫、レビュー）

Viewport と Robots の設定ポイント

Viewport Meta tag は mobile friendliness の基礎です。使用例： <meta name="viewport" content="width=device-width, initial-scale=1"> モバイル端末でページが正しく scale することを確認してください。Google の Mobile-First Indexing 導入以降、Viewport は事実上必須の tag です。

Robots Meta タグは、検索エンジンのクロールとインデックス登録の動作を制御します。index, follow（インデックス登録とリンク追跡を許可）、noindex（インデックス禁止）、nofollow（link follow を許可しない）。重要ページが noindex で block されていないことを確認し、admin backend など不要なページは index されないようにしてください。
