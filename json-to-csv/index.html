JSON 與 CSV 轉換常見問題

關於 JSON、CSV 格式轉換與 Excel 匯入的熱門疑問

JSON 與 CSV 是兩種完全不同用途的資料格式：

  • JSON（JavaScript Object Notation）是一種結構化資料格式，支援巢狀物件與陣列，適合程式間資料交換與 API 通訊。
  • CSV（Comma-Separated Values）是一種純文字表格格式，每行代表一筆記錄，每列代表一個欄位，是 Excel、Google Sheets、資料庫匯入匯出的通用格式。

以下情況適合將 JSON 轉為 CSV：

  • 需要將 API 資料匯入 Excel 或 Google Sheets 進行分析
  • 準備資料集進行機器學習或統計分析
  • 與非技術人員共享結構化資料（CSV 可直接用 Excel 開啟）
  • 將資料匯入資料庫（MySQL、PostgreSQL 支援 CSV 匯入）
  • 產生報表或試算表供決策者檢視

CSV 是二維表格格式（行 × 列），無法直接表示巢狀結構。本工具使用 點記法（Dot Notation）展平技術，自動將巢狀物件轉為平面欄位：

JSON 輸入

{
  "user": {
    "name": "Gary",
    "age": 30
  }
}

CSV 輸出

user.name,user.age
Gary,30

展平規則：

  • 物件 → 遞迴展平，Key 以點串接，例如 profile.address.city
  • 陣列 → 保留為 JSON 字串存入單一儲存格，避免欄位爆炸
  • Null → 依空值設定處理（空字串 / null / N/A / 0）

展平發生時，工具頂部會顯示橙色提示：「巢狀 JSON 已自動展平」。

將 CSV 匯入 Excel 有幾種方法：

  1. 直接開啟：下載 .csv 檔案後，直接用 Excel 開啟（選擇 UTF-8 編碼）
  2. 從資料匯入：Excel → 資料 → 從文字/CSV 匯入 → 選擇檔案 → 指定分隔符與編碼
  3. 拖曳到 Google Sheets：直接將 .csv 檔案拖入 Google Sheets 即可自動解析

UTF-8 BOM 是什麼？

BOM（Byte Order Mark）是位於檔案開頭的 ﻿ 標記。對於 CSV 檔案：

  • 啟用 BOM → Excel 會自動識別為 UTF-8 編碼，正確顯示中文、日文等 Unicode 字符
  • 無 BOM → Excel 可能以系統預設編碼（如 Big5）開啟，導致亂碼

💡 如果將 CSV 匯入 Excel 後中文顯示亂碼，請啟用「UTF-8 BOM」選項重新下載。

CSV 中的「C」代表 Comma（逗號），但實際上 CSV 可以使用不同的分隔符：

  • 逗號（,） — 最通用的標準，Excel 與 Google Sheets 的預設值。但如果資料中包含逗號（如地址「台北市, 台灣」），必須使用引號包裹。
  • 分號（;） — 部分歐洲地區 Excel 的預設分隔符（因逗號用作小數點）。如果你的 CSV 在 Excel 中無法正確分欄，試試分號。
  • Tab（\t） — 又稱為 TSV（Tab-Separated Values）。如果資料中頻繁出現逗號與分號，Tab 是最安全的選擇。許多資料庫匯入工具優先支援 TSV。

💡 不確定該用哪種？先用逗號，如果 Excel 顯示不正常，改用分號試試。

以下是最常見的幾種問題與解決方案：

  • 巢狀物件資料不見了？ 本工具會自動展平巢狀 JSON（如 profile.age），但如果 JSON 結構過於複雜（如深層巢狀超過 5 層），建議先簡化資料再轉換。
  • 陣列資料被截斷？ 陣列欄位會以 JSON 字串形式保留在單一儲存格中（如 "["a","b","c"]"），匯入 Excel 後可能無法自動展開。您可以在 Excel 中使用「資料 → 從表格/範圍」進一步處理。
  • 中文字元變成亂碼？ 啟用「UTF-8 BOM」選項後重新下載，Excel 將正確識別 UTF-8 編碼。
  • CSV 在 Excel 中全部擠在同一欄？ 改用「分號（;）」或「Tab（\t）」作為分隔符，或在 Excel 匯入時手動指定分隔符。

從 JSON 到 CSV：資料分析與試算表轉換完全指南

在現代資料處理工作流中，JSON（JavaScript Object Notation）與 CSV（Comma-Separated Values）分別代表了資料交換的兩個關鍵階段：JSON 是機器與機器之間的通訊格式，CSV 則是分析師與試算表之間的橋樑。掌握從 JSON 到 CSV 的轉換，是資料分析、後端開發與商業智慧領域的核心技能。

什麼是 JSON？

JSON 是一種輕量級、與語言無關的資料交換格式。它使用鍵值對（{"key": "value"}）與陣列（[item1, item2]）來組織資料。JSON 的核心優勢在於其結構化能力——它可以用巢狀物件來表達複雜的資料關係，這是 CSV 無法直接做到的。

在現代 Web 開發中，JSON 無所不在：RESTful API 的回應、資料庫查詢結果（MongoDB、PostgreSQL JSONB）、設定檔（Node.js package.json）、即時通訊（WebSocket）等。但當需要將這些資料匯入 Excel 或進行統計分析時，就需要將 JSON 轉換為 CSV 格式。

什麼是 CSV？

CSV 是一種純文字格式的表格資料表示法。它的歷史可追溯到 1970 年代，是最古老且最廣泛支援的資料交換格式之一。CSV 的設計極簡：每行一筆記錄，每列一個欄位，逗號分隔。

CSV 的優勢在於它的普遍性：Excel、Google Sheets、Numbers、資料庫管理工具、Python Pandas、R、MATLAB……幾乎所有處理表格資料的工具都支援 CSV。它是資料生態系統中的「通用語言」，適合長期存檔與跨平台交換。

JSON 與 CSV 詳細對比

JSON

  • 支援巢狀結構與複雜資料關係
  • 支援多種資料型別（字串、數字、布林、Null、陣列、物件）
  • 機器解析效率高，是 API 標準格式
  • 不適合直接匯入試算表
  • 檔案較大（含結構化標記）

CSV

  • 平面二維表格，每行一筆記錄
  • 僅支援純文字資料（所有值視為字串）
  • 人類可直接用 Excel 開啟與編輯
  • 適合資料分析、統計、報表
  • 檔案精簡，佔用空間小

CSV 在資料分析場景中的應用

  • Excel / Google Sheets：直接開啟或匯入 CSV，使用樞紐分析表、圖表、公式進行資料探索
  • Python Pandas：pd.read_csv() 是資料科學專案中最常見的資料載入方式
  • 資料庫匯入：MySQL 的 LOAD DATA INFILE、PostgreSQL 的 COPY 命令都原生支援 CSV
  • BI 工具：Tableau、Power BI、Looker Studio 等商業智慧工具都支援 CSV 作為資料來源
  • 機器學習：CSV 是 Kaggle 競賽、資料集發布、模型訓練輸入的標準格式
