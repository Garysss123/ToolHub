XML 與 JSON 轉換常見問題

關於 XML、JSON 格式轉換、API 資料交換與 Web Services 的熱門疑問

XML（可擴展標記語言）與 JSON（JavaScript 物件表示法）都是結構化資料格式，但在設計哲學上有顯著差異：

特性 XML JSON
可讀性 中等 — 標籤繁多 優異 — 簡潔輕量
型別支援 純文字，需透過 Schema 定義型別 原生支援字串、數字、布林、Null、陣列、物件
中繼資料 ✅ 內建 Attribute 機制 ❌ 無原生 Attribute
Namespace ✅ 支援 xmlns ❌ 不支援
註解 ✅ <!-- --> ❌ 不支援
解析速度 較慢（需解析標籤結構） 極快（原生 JavaScript 支援）
檔案體積 較大（重複的起始/結束標籤） 較小（最少符號）

選擇建議：需要複雜文件結構、Namespace、Attribute 中繼資料 → 選 XML；Web API、前後端通訊、輕量資料交換 → 選 JSON。許多現代 API 在接收 XML 後內部轉為 JSON 處理。

SOAP（Simple Object Access Protocol）是一種嚴謹的 XML 基礎通訊協定，於 1998 年由 Microsoft 提出。SOAP 訊息必須使用 XML 格式，並遵循嚴格的結構規範（Envelope → Header → Body）。

REST（Representational State Transfer）是一種輕量級的 API 設計風格，由 Roy Fielding 於 2000 年提出。REST API 通常使用 JSON，但也支援 XML 格式。

SOAP 特性

  • 嚴格的 WSDL 定義
  • 內建安全規範（WS-Security）
  • 有狀態 / 無狀態皆可
  • 僅支援 XML 格式
  • 企業級應用、金融系統

REST 特性

  • 資源導向設計（URI）
  • 無狀態（Stateless）
  • 支援 JSON / XML / 純文字
  • 使用標準 HTTP 方法（GET/POST/PUT/DELETE）
  • 現代 Web 與行動應用

許多企業在現代化過程中，會將 SOAP/XML 的 Legacy API 轉換為 REST/JSON 架構，本工具正是為此轉換場景設計。

Sitemap XML（網站地圖）是一種 XML 檔案，用於告知搜尋引擎您的網站上有哪些頁面、它們的更新頻率以及相對重要性。標準格式由 sitemaps.org 定義。

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2024-01-15</lastmod>
    <changefreq>daily</changefreq>
    <priority>1.0</priority>
  </url>
</urlset>

Sitemap XML 對 SEO 至關重要，因為：

  • 幫助搜尋引擎更快發現新頁面與更新內容
  • 確保大型網站的所有頁面都能被索引
  • 提供中繼資訊（最後更新時間、變更頻率）
  • 支援圖片、影片、新聞等特殊內容類型

本站的 Sitemap XML 位於：/sitemap.xml

RSS（Really Simple Syndication）是一種基於 XML 的內容訂閱格式，用於發布經常更新的內容（如部落格文章、新聞、Podcast）。RSS Feed 本質上就是一種 XML 檔案。

<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>ToolHub Blog</title>
    <link>https://toolhub.example.com/</link>
    <item>
      <title>JSON vs XML 全面比較</title>
      <pubDate>Mon, 15 Jan 2024 10:00:00 GMT</pubDate>
    </item>
  </channel>
</rss>

RSS Feed 的主要用途：

  • 讓使用者訂閱部落格、新聞網站的最新內容
  • Podcast 發布與分發（Apple Podcasts、Spotify 等平台使用 RSS）
  • 內容聚合與自動化工作流程
  • 社群媒體排程與內容再發布

XML 轉 JSON 時，Attribute 與 Text 節點的處理是最關鍵的設計決策。本工具提供三種選項：

  • @ 前綴（建議啟用）：將 XML Attribute 以 @ 前綴的 Key 表示。例如 <book category="fiction"> → "@category": "fiction"。這種方式清楚區分 Attribute 與子元素。
  • #text 節點：當元素同時有 Attribute 與文字內容時，文字內容會放在 #text 鍵中。例如 <title lang="en">Hello</title> → {"@lang": "en", "#text": "Hello"}。
  • 保留 Attribute：關閉此選項時，所有 Attribute 將被忽略，僅保留元素內容。適用於只需要文本內容的場景。

範例：

XML: <book id="b1" lang="en">The Hobbit</book>

✅ @前綴 + #text: {"@id": "b1", "@lang": "en", "#text": "The Hobbit"}
❌ 無 Attribute:    "The Hobbit"

100% 安全。本工具採用純前端（Client-side）架構，所有 XML 解析與 JSON 轉換都在您的瀏覽器中完成，不會將任何資料上傳至任何伺服器。

這意味著：

  • 您的 API 規格、Sitemap 資料、RSS Feed 配置絕不會離開您的電腦
  • 不需要網路連線即可執行轉換（除了第一次載入頁面）
  • 沒有任何後端伺服器會儲存或處理您的內容
  • 即使是 ToolHub 的管理者也無法存取您輸入的資料

無論是 SOAP API 的 XML 請求、Sitemap 設定或 Legacy 系統的資料，在這裡處理都是安全的。

XML 轉 JSON 時，由於兩種格式的結構差異，轉換結果可能需要調整。以下是常見的結構變更與處理方式：

  • 重複元素自動變陣列：XML 中同名的重複子元素（如多個 <item>）會被轉換為 JSON 陣列。
  • Attribute 獨立為屬性：啟用 @ 前綴時，Attribute 會成為獨立的 JSON Key，不會與子元素混淆。
  • 空元素處理：空的 XML 元素（<element></element>）可能轉為 Null 或空字串，取決於設定。
  • 混合內容：元素同時包含文字與子元素時，文字會放入 #text 鍵。

建議：轉換後對照原始 XML 檢查 JSON 結構，特別注意陣列與巢狀物件是否正確。您可以使用 Tree View 模式直覺檢視 JSON 結構。

從 XML 到 JSON：現代 Web 開發的資料格式演進與實戰指南

在 Web 技術超過二十五年的發展歷程中，XML（eXtensible Markup Language）與 JSON（JavaScript Object Notation）分別代表了兩個時代的資料交換標準。從 1998 年 XML 成為 W3C 推薦標準，到 2010 年代 JSON 全面崛起成為 Web API 的事實標準，理解兩者的轉換不僅是技術需求，更是理解 Web 架構演進的重要視角。

什麼是 XML？

XML（可擴展標記語言）由 W3C 於 1998 年制定，是一種可擴展的標記語言，設計目標是「既被人類閱讀，也被機器解析」。XML 使用自定義標籤（Tags）來描述資料結構，並支援 Attribute（屬性）、Namespace（命名空間）、Schema（XSD） 等豐富功能。

XML 的設計哲學是「嚴格而完整」。每個 XML 文件必須有一個根元素，所有標籤必須正確關閉，Attribute 值必須使用引號。這種嚴謹性使其非常適合企業級應用、金融系統、醫療記錄、法律文件等需要高度結構化與驗證的場景。主要應用領域包括：

  • SOAP Web Services — 企業級 API 通訊協定，嚴格依賴 XML 格式
  • Sitemap XML — 搜尋引擎網站地圖標準格式
  • RSS / Atom Feed — 內容訂閱與發布格式
  • SVG — 可縮放向量圖形（基於 XML）
  • Docx / Xlsx — Microsoft Office 文件格式（內部使用 XML）
  • XHTML — 嚴格的 HTML 版本
  • Configuration Files — Maven POM、Ant Build、Spring XML 等

什麼是 JSON？

JSON（JavaScript Object Notation）由 Douglas Crockford 於 2001 年規範化，是一種輕量級的資料交換格式。JSON 源自 JavaScript 語法的子集，使用鍵值對與陣列組織資料，語法簡潔、解析效率極高。

JSON 的設計哲學是「簡潔而高效」。沒有結束標籤、沒有 Attribute、沒有 Namespace — 這種極簡設計使其在 Web 開發中迅速普及。JSON 的主要優勢領域：

  • RESTful API — 現代 Web API 的首選格式
  • NoSQL 資料庫 — MongoDB、CouchDB 等使用 JSON-like 文件儲存
  • 前端開發 — React、Vue、Angular 等框架原生處理 JSON
  • 設定檔 — package.json、tsconfig.json、.eslintrc.json 等
  • 即時通訊 — WebSocket 訊息格式

XML 與 JSON 的詳細對比

XML 適用場景

  • SOAP Web Services / WSDL
  • Sitemap SEO 提交
  • RSS / Atom Feed 發布
  • SVG 向量圖形
  • Office 文件格式
  • 複雜文件結構與混合內容
  • 需要 Schema 驗證的資料交換

JSON 適用場景

  • REST / GraphQL API
  • 前端 JavaScript 應用
  • NoSQL 資料庫文件
  • 行動應用 App 資料交換
  • IoT 裝置資料格式
  • 伺服器端設定檔
  • 快取與訊息佇列

XML 轉 JSON 實戰範例

XML 輸入

<?xml version="1.0" encoding="UTF-8"?>
<api-response>
  <status>success</status>
  <data>
    <user id="u001" role="admin">
      <name>John Doe</name>
      <email>john@example.com</email>
      <permissions>
        <permission>read</permission>
        <permission>write</permission>
        <permission>delete</permission>
      </permissions>
    </user>
  </data>
  <meta>
    <requestId>req-2024-001</requestId>
    <timestamp>2024-01-15T10:30:00Z</timestamp>
  </meta>
</api-response>

JSON 輸出

{
  "api-response": {
    "status": "success",
    "data": {
      "user": {
        "@id": "u001",
        "@role": "admin",
        "name": "John Doe",
        "email": "john@example.com",
        "permissions": {
          "permission": [
            "read",
            "write",
            "delete"
          ]
        }
      }
    },
    "meta": {
      "requestId": "req-2024-001",
      "timestamp": "2024-01-15T10:30:00Z"
    }
  }
}

可以看到，Attribute（id、role）以 @ 前綴保留，重複的 <permission> 元素自動合併為陣列。
