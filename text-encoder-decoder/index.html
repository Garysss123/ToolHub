常見問題

Base64 和 URL Encode 有什麼差別？
Base64 是一種將二進位資料編碼為 ASCII 字串的方法，常用於在文字協定（如 HTTP、Email）中傳輸圖片、檔案等二進位內容。它使用 A-Z、a-z、0-9、+、/ 及 =（填充）共 65 個字元。

URL Encode（又稱 Percent-encoding） 則是用於將 URL 中的特殊字元（如中文、空格、#、& 等）轉換為 %XX 格式，使其能在 URL 中安全傳輸。

核心差異：Base64 是將二進位 → 文字編碼，URL Encode 是將文字 → URL 安全格式。兩者的用途完全不同。
HTML Entity 什麼時候使用？
HTML Entity 用於在 HTML 文件中顯示保留字元（如 <、>、&）或無法直接輸入的字元（如版權符號 ©）。

常見使用時機：
• 在 HTML 中展示程式碼片段（避免被瀏覽器誤解為 HTML 標籤）
• 顯示特殊符號（©、®、™、€ 等）
• XSS 防禦——轉義使用者輸入中的 HTML 特殊字元
• 在網頁中嵌入第三方內容（如 RSS Feed、使用者評論）
Unicode Escape（\\uXXXX）是什麼？
Unicode Escape 是將字元以 \\uXXXX 的形式表示，其中 XXXX 是該字元的 Unicode 碼點（Code Point）的十六進位值。

例如：
• A → \\u0041
• 世 → \\u4E16
• 界 → \\u754C

這種表示法常見於：JSON 資料中的非 ASCII 字元、JavaScript 原始碼中需要確保編碼一致性的場景、以及某些僅支援 ASCII 的舊系統中。
JSON Escape 的用途是什麼？
JSON Escape 將字串中的特殊字元轉義，使其符合 JSON 格式規範。JSON 規範（RFC 7159）要求以下字元必須被轉義：

• " → \\"（雙引號）
• \\ → \\\\（反斜線）
• / → \\/（斜線，可選）
• \\b（退格）、\\f（換頁）、\\n（換行）、\\r（回車）、\\t（製表）

未正確轉義的 JSON 會導致 JSON.parse() 失敗。這在 API 開發、資料序列化、以及處理使用者輸入時非常重要。
JavaScript Escape 和 JSON Escape 有什麼不同？
雖然兩者看起來相似，但它們適用的規範有所不同：

JSON Escape 遵循 JSON 規範（RFC 7159）。嚴格來說，JSON 字串中只需要轉義雙引號、反斜線和控制字元（U+0000~U+001F）。

JavaScript Escape 則涵蓋更廣泛的 JavaScript 字串語法，包括轉義單引號（在單引號字串中）、以及使用 \\xHH（十六進位）和 \\uHHHH（Unicode）表示法。

實務上，如果你要產生 JSON 資料，請使用 JSON Escape；如果你要產生 JavaScript 程式碼字串，請使用 JavaScript Escape。
自動偵測（Auto Detect）的判斷邏輯是什麼？
當你點擊「自動偵測」按鈕或貼上內容時，系統會依序嘗試以下判斷：

1. Base64： 檢查是否符合 Base64 字元集（A-Za-z0-9+/=），且長度為 4 的倍數。嘗試解碼後確認是否為可讀文字。
2. URL Encode： 檢查是否包含 %XX 格式，且解碼後為有效 UTF-8。
3. HTML Entity： 檢查是否包含 &、<、>、&#XXXX; 等格式。
4. Unicode Escape： 檢查是否包含 \\uXXXX 格式。
5. JSON Escape： 檢查是否包含 \\n、\\t、\\" 等 JSON 跳脫序列。

如果匹配到多種格式，系統會優先選擇最可信的結果。如果都無法匹配，則視為一般文字。

文字編碼的世界：從 ASCII 到 Unicode

在電腦科學中，「文字編碼」是將字元轉換為電腦可以處理的二進位格式的過程。從最早期的 ASCII（僅 128 個字元），到現在的 Unicode（涵蓋超過 14 萬個字元），文字編碼的演進反映了全球資訊交流的需求增長。

為什麼需要這麼多種編碼方式？

不同的編碼方式服務於不同的場景。Base64 解決的是「二進位資料在文字協定中傳輸」的問題；URL Encode 解決的是「特殊字元在網址中安全傳遞」的問題；HTML Entity 解決的是「保留字元在 HTML 中正確顯示」的問題；Unicode Escape 解決的是「非 ASCII 字元在純 ASCII 環境中表示」的問題。

每種編碼方式都有其獨特的適用場景，這也是為什麼開發者需要熟悉多種編碼格式的原因。

自動偵測的實用價值

在實際開發中，我們常常會遇到無法確認編碼格式的資料——可能是來自第三方 API 的回應、從資料庫匯出的欄位、或是其他系統傳送的訊息。這時，自動偵測功能可以幫助你快速辨識資料的編碼方式，省去手動嘗試不同解碼方式的時間。

然而需要注意的是，自動偵測並非 100% 準確。某些編碼格式（如 Base64 與一般文字）在某些情況下可能難以區分。如果偵測結果不正確，建議手動切換到對應的格式進行編解碼。

安全性考量

在處理使用者輸入或第三方資料時，正確的編碼/轉義是防止安全漏洞的重要環節。例如：

XSS 防禦：在網頁中顯示使用者輸入時，應使用 HTML Entity Escape 來避免惡意指令碼注入。

JSON 注入：在構建 JSON 資料時，確保字串值經過 JSON Escape，避免破壞 JSON 結構。

Command Injection：在拼接系統命令時，應確保特殊字元被正確轉義或使用參數化查詢。

本工具的所有運算都在瀏覽器端完成，你的資料不會被傳送到任何伺服器，確保資料安全。
