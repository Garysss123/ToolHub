Schema Generator 是一個雙模運作的結構化資料工具。產生模式：透過表單填寫，自動生成符合 Schema.org 規範的 JSON-LD 程式碼，無需手寫 JSON。分析模式：貼上現有的 JSON-LD，工具會自動檢測 Schema 類型、驗證欄位完整度、檢查是否符合 Google 建議，並提供改善建議。適用於 WebSite、Organization、Article、FAQPage、Product 等 10 種常見 Schema 類型。
Schema.org 是由 Google、Microsoft、Yahoo 和 Yandex 共同推出的結構化資料標記標準。它透過統一的詞彙表（Vocabulary），讓網站管理者以標準化方式描述網頁內容的意義，例如告訴搜尋引擎「這是一個產品的價格」、「這是一篇文章的作者」。搜尋引擎讀取這些標記後，可以在搜尋結果中顯示更豐富的呈現方式（Rich Results），如評價星級、FAQ 摺疊區、麵包屑導航等，提升點擊率與搜尋曝光。
JSON-LD（JavaScript Object Notation for Linked Data）是目前 Google 推薦的結構化資料實作方式。與 Microdata 不同，JSON-LD 是獨立於 HTML 之外的程式碼區塊，放在 <script type="application/ld+json"> 標籤中。優點包括：(1) 不影響 HTML 結構；(2) 易於維護和更新；(3) 可嵌入多組獨立的 Schema；(4) 支援動態產生。Google 明確表示 JSON-LD 是他們偏好的實作方式，本工具也使用 JSON-LD 格式輸出。
結構化資料雖然不是 Google 排名演算法的直接因素，但它能讓搜尋結果呈現 Rich Results（豐富結果），例如：商品評價星級、FAQ 摺疊問答、麵包屑導航路徑、文章作者與日期等。這些視覺元素能顯著提升搜尋結果的注目度和點擊率（CTR），間接提升 SEO 表現。此外，隨著 AI 搜尋引擎（如 Google SGE、Perplexity）的普及，結構化資料成為 AI 理解網站內容的重要橋樑。
驗證 Schema.org 結構化資料是否正確，可以使用以下方法：(1) Google Rich Results Test — Google 官方提供的測試工具，可直接驗證結構化資料是否符合 Google Rich Results 規範；(2) Schema.org Validator — 由 W3C 提供的結構化資料驗證工具；(3) 本工具的分析模式 — 貼上 JSON-LD 即可檢測基本完整度、必填欄位與 Google 建議。建議在部署到正式站前至少通過上述任一驗證工具的檢測。
可以。一個網頁可以同時包含多組 Schema.org JSON-LD 程式碼，只要各自包在 <script type="application/ld+json"> 標籤中即可。例如：一個產品的頁面可以同時包含 Product Schema（描述產品資訊）、BreadcrumbList Schema（描述導航路徑）、以及 WebSite Schema（描述整個網站）。Google 也會合併解析這些資料，用於不同的 Rich Results 呈現。本工具每次產生一組 Schema，您可多次使用並同時放置於同一網頁中。
JSON-LD 格式的結構化資料可以放在 HTML 的 <head> 或 <body> 中的任何位置，只需使用 <script type="application/ld+json"> 標籤包裹即可。最佳實務建議：將全站的 Schema（如 WebSite、Organization）放在 <head> 中統一管理；將頁面特定的 Schema（如 Article、FAQPage、Product）放在對應內容區塊附近的 <body> 中。Google 對放置位置沒有限制，但要確保結構化資料的內容與頁面實際顯示的內容一致。

深入了解 Schema.org 結構化資料與其在 SEO 中的應用

Schema.org 是什麼？結構化資料完整入門指南

Schema.org 是一個由 Google、Microsoft、Yahoo 與 Yandex 共同發起的結構化資料詞彙表（Vocabulary），目的是建立一套統一的標記標準，讓網站能夠以機器可讀的方式描述網頁內容的語意。結構化資料透過標準化的屬性（如 name、description、price、rating）來標記網頁中的實體對象（產品、文章、事件、組織等）。

在 SEO 領域中，結構化資料是實現 Rich Results（豐富結果）的基礎。Google 支援超過 30 種 Rich Results 類別，包括商品評價（Product）、問答（FAQ）、食譜（Recipe）、事件（Event）等。網站加入對應的結構化資料後，搜尋結果中就可能顯示星級評分、價格範圍、問答預覽等醒目元素，顯著提升點擊率（CTR）。

JSON-LD 格式完整教學

JSON-LD（JavaScript Object Notation for Linked Data）是目前 Google 官方最推薦的結構化資料實作方式。與 Microdata 和 RDFa 不同，JSON-LD 完全獨立於 HTML 結構之外，透過獨立的 <script type="application/ld+json"> 標籤嵌入，不影響頁面的視覺呈現和 HTML 結構。

一個標準的 JSON-LD 結構包含三個核心元素：@context（定義使用的詞彙表，固定為 "https://schema.org"）、@type（定義實體類型，如 WebSite、Article）、以及屬性鍵值（依不同類型而異，如 name、description、url）。JSON-LD 支援巢狀結構，可以描述複雜的關聯關係，如產品的供應商、文章的作者等。

FAQ Schema 完整指南

FAQ Schema（FAQPage）是 Google Rich Results 中最受歡迎的結構化資料類型之一。啟用 FAQ Schema 後，您的問答內容可以在搜尋結果中直接展開顯示，讓使用者無需點進網頁即可獲得解答，這不僅提升使用者體驗，也大幅提高搜尋結果的注目度。

FAQ Schema 使用 mainEntity 屬性來定義每個問答組，每個問答組包含 Question（問題名稱）和 AcceptedAnswer（答案文字）。Google 建議 FAQ 頁面應包含至少 2 組問答，且答案需為完整且有幫助的內容。注意：FAQ Schema 僅適用於頁面主要內容為問答形式的網頁，不應將一般頁面的部分內容標記為 FAQ。

Product Schema 完整指南

Product Schema 是電商網站必備的結構化資料。啟用後，搜尋結果中可能顯示產品的價格、庫存狀態、評價星級和評價數量等豐富資訊，極大提升商品在搜尋結果中的吸引力。Google 支援 Product 的 Rich Results 包含價格標籤、購物按鈕和評價資訊。

Product Schema 的核心必填欄位至少需要提供 name（產品名稱）和 offers（供應資訊）。建議欄位包括 description（產品描述）、brand（品牌）、sku（庫存單位）、image（產品圖片）、aggregateRating（評價總覽）以及 review（使用者評論）。提供越完整的 Product Schema，搜尋結果呈現越豐富。

SoftwareApplication Schema 完整指南

SoftwareApplication Schema 是軟體產品和應用的專用結構化資料類型。無論是行動 App、桌面軟體、網頁應用還是 SaaS 產品，都能透過此 Schema 向搜尋引擎描述軟體的詳細資訊。啟用後，Google 搜尋結果可能會顯示軟體名稱、評分、作業系統相容性、價格和下載連結等豐富資訊。

實作 SoftwareApplication Schema 時，建議包含以下欄位：name（軟體名稱）、description（軟體描述）、operatingSystem（支援的作業系統，如 Windows、macOS、Android）、applicationCategory（應用類別，如 Game、Multimedia、DeveloperApplication）以及 offers（價格資訊）。如果軟體有使用者評分，也可以加入 aggregateRating 顯示平均評價。

BreadcrumbList Schema 完整指南

BreadcrumbList Schema（麵包屑導航結構化資料）是提升網站導覽體驗和搜尋結果顯示的重要工具。啟用後，Google 搜尋結果中的網頁標題上方會顯示導覽路徑（如 首頁 > 產品 > 筆記型電腦），幫助使用者快速理解頁面在網站中的位置，並提升搜尋結果的點擊率。

BreadcrumbList Schema 使用 itemListElement 陣列來定義每個導覽層級，每個元素包含 @type: ListItem、position（位置順序，從 1 開始）、name（顯示名稱）和 item（對應網址）。實作時應確保麵包屑路徑與頁面實際的導航層級一致。Google 建議 BreadcrumbList 至少包含 2 個項目，且最後一項應為當前頁面。
