關於 HTTP 狀態碼的常見疑問與解答

什麼是 HTTP 狀態碼？為什麼重要？

HTTP 狀態碼（HTTP Status Code） 是伺服器在回應客戶端（瀏覽器、API 客戶端等）請求時，回傳的三位數字代碼。它們是網際網路通訊的基礎語言，告訴客戶端請求的結果。

狀態碼分為五個類別：

  • 1xx（資訊） — 請求正在處理中
  • 2xx（成功） — 請求已成功處理
  • 3xx（重定向） — 需要進一步操作以完成請求
  • 4xx（客戶端錯誤） — 請求有誤，客戶端需修正
  • 5xx（伺服器錯誤） — 伺服器端出現問題

為什麼重要？ 狀態碼不僅是除錯工具，還直接影響 SEO 排名、使用者體驗、快取策略 與 API 設計。正確的狀態碼是建立可靠 Web 服務的基礎。

301 與 302 重定向有什麼不同？

301 Moved Permanently 表示資源已永久移動到新網址。搜尋引擎會將舊網址的 SEO 權重（PageRank、連結 juice）完全轉移到新網址，並在索引中更新為新網址。

302 Found 表示資源暫時移動。搜尋引擎不會轉移 SEO 權重到新網址，會繼續索引舊網址。

主要差異：

  • 301：永久性變更，SEO 權重轉移，適用於網站改版、HTTPS 遷移、URL 重構
  • 302：暫時性變更，SEO 權重不轉移，適用於 A/B 測試、臨時維護頁面、季節性促銷

⚠️ 常見錯誤：很多網站誤用 302 做為永久重定向，導致 SEO 權重分散。如果確定網址不會改回，請務必使用 301。

404 與 410 有什麼不同？

404 Not Found 表示資源暫時找不到，但可能未來會恢復。這是最常見的錯誤頁面。

410 Gone 表示資源已永久刪除，且沒有轉址。這是一個比 404 更強烈的訊號。

對 SEO 的影響差異很大：

  • 404：搜尋引擎會在一段時間內繼續嘗試抓取，多次 404 後才會從索引中移除
  • 410：搜尋引擎會更快地將該網址從索引中移除，因為明確被告知資源已永久消失

使用建議：如果內容是意外刪除或暫時下架，使用 404。如果是確定不再回復的商品頁、舊版文章、已停產的產品，請使用 410 以加速搜尋引擎清理索引。

500 系列伺服器錯誤該如何排查？

5xx 錯誤代表伺服器端出了問題，以下是常見 5xx 錯誤的排查方針：

500 Internal Server Error

最通用的伺服器錯誤。檢查伺服器錯誤日誌（/var/log/、Nginx/Apache 日誌、應用程式日誌），最常見原因是程式碼例外、資料庫連線失敗或 .htaccess 語法錯誤。

502 Bad Gateway

代理伺服器收到上游無效回應。常見於 Nginx + PHP-FPM 架構：檢查 PHP-FPM 是否執行中，或上游應用伺服器（如 Gunicorn、uWSGI）是否正常運作。

503 Service Unavailable

伺服器暫時無法處理請求。檢查是否在進行維護、伺服器是否過載。查看 Retry-After 標頭了解預估恢復時間。

504 Gateway Timeout

代理伺服器等待上游回應超時。增加 Nginx proxy_read_timeout、PHP max_execution_time，或優化資料庫慢查詢。

通用排查步驟：① 檢查伺服器錯誤日誌 → ② 確認資料庫連線 → ③ 檢查記憶體與 CPU 使用率 → ④ 確認最近是否有程式部署變更 → ⑤ 重試有時會恢復（如果是短暫問題）。

HTTP 狀態碼對 SEO 有什麼影響？

HTTP 狀態碼對搜尋引擎排名有直接影響：

  • 200 OK — 理想狀態，搜尋引擎正常索引內容
  • 301 Moved Permanently — SEO 權重無縫轉移到新網址
  • 302 Found — 不轉移權重，可能導致分數分散
  • 304 Not Modified — 節省爬蟲預算（Crawl Budget）
  • 403 Forbidden — 搜尋引擎無法存取內容
  • 404 Not Found — 過多 404 損害網站品質評分
  • 410 Gone — 搜尋引擎會更快移除索引
  • 429 Too Many Requests — 可能導致爬蟲暫時停止抓取
  • 500+ 系列 — 持續的伺服器錯誤會嚴重損害 SEO 排名

SEO 最佳實踐：定期監控網站的 HTTP 狀態碼分佈，使用 Google Search Console 檢查 404 與 500 錯誤，建立自訂 404 頁面提升使用者體驗，並確保所有頁面回傳正確的狀態碼。

哪些 HTTP 狀態碼可以快取？

HTTP 快取策略與狀態碼密切相關。以下是常見狀態碼的快取行為：

  • 200 OK — 可快取（取決於 Cache-Control 標頭）
  • 203 Non-Authoritative Info — 可快取
  • 206 Partial Content — 可快取（用於分段內容）
  • 301 Moved Permanently — 瀏覽器會永久快取此重定向
  • 304 Not Modified — 快取機制本身的一部分
  • 308 Permanent Redirect — 瀏覽器會永久快取
  • 302 / 307 — 僅在有明確 Cache-Control 時快取
  • 404 — 通常可（但最好不要）快取
  • 410 Gone — 通常可快取
  • 503 Service Unavailable — 可設定 Retry-After 搭配快取

💡 提醒：快取行為最終由 Cache-Control、Expires 與 ETag 等標頭決定，同一狀態碼可能因不同的標頭設定而有不同的快取行為。

如何在瀏覽器開發者工具中查看 HTTP 狀態碼？

三大主流瀏覽器皆內建開發者工具，可輕鬆檢視 HTTP 狀態碼：

Chrome / Edge DevTools

按 F12 或 Ctrl+Shift+I → 切換到 Network（網路） 面板 → 重新載入頁面 → 點擊任一請求即可在 Headers（標頭） 中看到 Status Code。

Firefox DevTools

按 F12 → Network（網路） 面板 → 請求清單直接顯示狀態碼（顏色標示：2xx 綠色、4xx 橘色、5xx 紅色）。

Safari Web Inspector

啟用開發者選單（偏好設定 → 進階）→ 網路 標籤 → 檢視每個請求的狀態碼。

💡 快速技巧：在 Network 面板中按 Status 排序，可以快速找到所有 4xx/5xx 錯誤請求。

深入了解 HTTP 狀態碼的運作原理與最佳實踐

什麼是 HTTP 狀態碼？

HTTP 狀態碼（HTTP Status Code） 是網際網路通訊中最基礎也最重要的元件之一。每當瀏覽器、搜尋引擎爬蟲或 API 客戶端向伺服器發出請求時，伺服器都會回傳一個三位數字的狀態碼，用以表示請求的結果。

這三個數字的每一個位數都有其意義：

  • 1xx — 資訊回應：請求已收到，處理中
  • 2xx — 成功：請求已成功接收、理解並接受
  • 3xx — 重定向：需要進一步操作才能完成請求
  • 4xx — 客戶端錯誤：請求包含錯誤語法或無法完成
  • 5xx — 伺服器錯誤：伺服器無法完成有效請求

了解 HTTP 狀態碼對於 Web 開發、API 設計、SEO 優化 與 系統管理 都是必備的基礎知識。

301 vs 302：重定向策略完整解析

重定向（Redirect）是網站管理中常用的技術，但 301 與 302 的選擇對 SEO 有截然不同的影響。

301 永久重定向

使用 301 代表告訴搜尋引擎：「這個網址已經永久搬家了，請把舊網址的所有排名和權重全部轉移到新網址。」這是 網站改版、HTTPS 遷移、網址重構 時的正確選擇。

SEO 影響：PageRank 轉移率約為 90-99%，是權重傳遞最完整的方式。Google 會將舊網址從索引中移除，改用新網址。

302 暫時重定向

使用 302 代表告訴搜尋引擎：「這個網址只是暫時被移動，請繼續索引舊網址。」這是 A/B 測試、臨時維護頁面、季節性活動 時的正確選擇。

SEO 影響：搜尋引擎不會將權重轉移到新網址，會繼續保留舊網址在索引中。

實戰建議：

  • ✅ 從 HTTP 升級到 HTTPS → 301
  • ✅ 網站更換域名 → 301
  • ✅ 合併多個頁面 → 301
  • ⚠️ 短期促銷頁面 → 302
  • ⚠️ A/B 測試不同版本 → 302
  • ❌ 使用 302 做永久重定向 → 常見錯誤，會導致 SEO 權重分散

404 vs 410：當內容不存在時的回應選擇

當使用者或搜尋引擎請求一個不存在的 URL 時，伺服器可以回傳 404 Not Found 或 410 Gone。兩者的差別不僅在於技術上的語義，更影響搜尋引擎的行為。

404 Not Found

表示資源「暫時」找不到。伺服器不知道該資源是否會再次上線。這是預設的「資源不存在」回應，也是最通用的選擇。

  • 適合：意外刪除、暫時下架、URL 拼寫錯誤
  • 搜尋引擎行為：會在一段時間內繼續嘗試抓取，多次 404 後才會從索引中移除

410 Gone

表示資源「永久」消失，且沒有提供替代網址。這是一個比 404 更明確的訊號。

  • 適合：已停產的產品頁、已刪除的使用者內容、已退役的 API 版本
  • 搜尋引擎行為：會更快地將該網址從索引中移除，因為明確被告知資源已消失

SEO 建議：對於確定不再恢復的頁面，請使用 410 而非 404，可加速搜尋引擎清理索引。對於不確定是否會恢復的頁面，使用標準的 404 即可。

500 系列伺服器錯誤：診斷與修復

5xx 錯誤代表伺服器端出現問題，這對 SEO 和使用者體驗都是最大的威脅。持續的 5xx 錯誤會讓搜尋引擎降低對網站的信任度。

常見 5xx 錯誤與解決方案

  • 500 Internal Server Error — 最通用的伺服器錯誤。檢查伺服器錯誤日誌、應用程式日誌、.htaccess 語法
  • 502 Bad Gateway — 代理/閘道收到無效回應。檢查 Nginx + PHP-FPM / Gunicorn 等架構
  • 503 Service Unavailable — 伺服器暫時無法處理。檢查維護狀態、伺服器負載、確保設定 Retry-After 標頭
  • 504 Gateway Timeout — 上游伺服器回應逾時。增加代理超時設定、優化資料庫查詢

5xx 錯誤對 SEO 的影響

Google 等搜尋引擎對於持續回傳 5xx 錯誤的網站會顯著降低排名。如果搜尋引擎爬蟲在抓取時遇到 503，它會理解這是暫時問題並稍後再試。但如果持續遇到 500 或 502，搜尋引擎就會認為網站不可靠，進而降低排名。

緊急應對：當發生大規模 5xx 錯誤時，設定 503 狀態碼並搭配 Retry-After 標頭，告訴搜尋引擎這是暫時的。這比讓爬蟲隨機遇到錯誤要好得多。

HTTP 狀態碼與 SEO 最佳實踐

在 SEO 工作中，HTTP 狀態碼的管理是不可或缺的一環。以下是幾個關鍵的最佳實踐：

定期監控狀態碼分佈

使用 Google Search Console 定期檢查網站的狀態碼報告。特別注意 404 與 5xx 錯誤的數量與趨勢。大量 404 可能代表網站結構問題或大量失效的外部連結。

正確使用重定向

301 用於永久變更，302 用於暫時變更。避免重定向鏈（A → B → C），盡量讓重定向一步到位。避免重定向迴圈（A → B → A）。

自訂 404 頁面

提供友善的自訂 404 頁面，包含回到首頁的連結和搜尋功能。這不僅提升使用者體驗，也能減少跳出率對 SEO 的負面影響。

利用快取提升效能

正確設定 Cache-Control 與 ETag 標頭，讓 304 Not Modified 充分發揮作用，減少伺服器負載並加快頁面載入速度。

監控伺服器健康

設置伺服器監控警報，在出現大量 5xx 錯誤時即時通知。使用 CDN 可以在源站伺服器故障時提供備援或維護頁面。

總結：HTTP 狀態碼是網站健康的核心指標。正確理解和運用每個狀態碼，不僅能提升開發效率，更能顯著改善網站的 SEO 排名與使用者體驗。使用 ToolHub 的 HTTP Status Code Lookup 工具，隨時查詢任何狀態碼的詳細說明與最佳處理方式。
