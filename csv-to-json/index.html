CSV 與 JSON 轉換常見問題

關於 CSV、JSON 格式轉換與型別判斷的熱門疑問

CSV 是一種通用表格格式，但在許多現代開發場景中，JSON 才是首選資料格式：

  • API 開發：RESTful API、GraphQL、WebSocket 等通訊協定都以 JSON 為標準格式，將 CSV 匯入 API 前需要先轉為 JSON。
  • NoSQL 資料庫：MongoDB、Firebase 等使用 JSON 文件，CSV 需要轉換後才能匯入。
  • JavaScript / TypeScript：前端與 Node.js 專案原生支援 JSON，可直接 import 或 JSON.parse()。
  • Python 資料科學：Pandas 可讀取 CSV，但許多 API 回應與 ML 模型輸入需要 JSON。
  • AI / LLM 工作流：AI 模型的訓練資料、Prompt 範本、Function Calling 結構定義通常使用 JSON。

CSV 本質上全是文字，但 JSON 支援多種資料型別。型別自動判斷功能會辨識每個值的最佳類型：

CSV 輸入

name,age,active,score
Gary,30,true,95.5

自動判斷輸出

{
  "name": "Gary",
  "age": 30,
  "active": true,
  "score": 95.5
}

轉換規則：

  • "true" / "false" → 布林值
  • "30"、"95.5"、"-5" → 數字
  • "null" → null
  • 空值 → 依設定的空值處理方式
  • 其餘 → 字串

💡 選擇「全部視為字串」模式可保留 CSV 中的原始文字，不做任何型別轉換。

當 CSV 欄位名稱包含點號（如 profile.age、address.city），Nested Object 模式會自動將它們展開為巢狀 JSON 物件：

CSV 輸入（點記法）

profile.age,profile.city
30,台北

Nested Object 輸出

{
  "profile": {
    "age": 30,
    "city": "台北"
  }
}

三種輸出模式對比：

  • Object Array — 每筆資料一個物件，組成陣列。最通用的預設模式。
  • Key-Value Object — 以指定欄位為 Key，將整筆資料作為 Value，輸出一整個物件。
  • Nested Object — 自動將點記法欄位展開為多層巢狀物件。

💡 偵測到點記法欄位時，工具頂部會顯示藍色提示：「偵測到巢狀欄位（點記法）」。

正確設定分隔符與 BOM 是順利解析 CSV 的關鍵：

  • 分隔符（Delimiter）： 標準 CSV 使用逗號（,），但部分試算表工具（如歐洲版 Excel）使用分號（;）。如果資料中包含大量逗號，Tab（\t）是更安全的選擇。本工具會自動根據您選擇的分隔符解析 CSV。
  • UTF-8 BOM 自動偵測： 部分軟體（如 Excel 匯出的 CSV）會在檔案開頭加入 BOM 標記（﻿）。啟用「自動偵測 BOM」後，工具會自動識別並移除 BOM，避免第一個欄位名稱出現異常字符。
  • Trim 空白： 啟用後會自動清除每個欄位前後的空白字元，避免不必要的空格導致資料比對錯誤。

💡 如果 CSV 第一欄名稱開頭有異常字符，請啟用「自動偵測 BOM」。

本工具會自動檢查 CSV 中的常見問題並顯示行號與原因：

  • 欄位數不一致： 如果某行的欄位數量與標題列（或第一行）不符，工具會標示具體行號，並顯示該行與期望的欄位數差異。
  • 空欄位： 檢查是否有空白的欄位值，並顯示位置（第幾行第幾欄）。
  • 重複 Header： 如果標題列中有重複的欄位名稱，重複的 Key 會被重新命名（如 name → name_2），以確保 JSON Key 唯一性。
  • 語法問題： 檢查引號配對是否完整、是否有非預期的換行等。

所有錯誤都會在工具頂部的錯誤面板中顯示，並標明精確的行號與欄位數，方便您快速修正。

從 CSV 到 JSON：資料轉換與 API 整合完全指南

在現代開發工作流中，CSV（Comma-Separated Values）與 JSON（JavaScript Object Notation）分別擔任了不同的角色：CSV 是試算表與資料庫匯出的通用格式，JSON 則是 API 與 NoSQL 生態系的共通語言。掌握從 CSV 到 JSON 的轉換，是後端開發、資料工程與 AI 應用開發的核心技能。

什麼是 CSV？

CSV 是最古老且最廣泛支援的純文字表格格式之一。它的設計極簡：每行一筆記錄，每列一個欄位，使用特定分隔符（通常是逗號）分隔。CSV 的優勢在於其普遍性——幾乎所有資料處理工具都支援 CSV，包括 Excel、Google Sheets、資料庫管理系統、Python Pandas 等。

CSV 廣泛應用於資料匯出（資料庫查詢結果、財務報表、客戶名單）、資料交換（不同系統間的批次匯入匯出）、以及機器學習資料集。但當需要將這些資料用於 API、JavaScript 或 NoSQL 資料庫時，就需要轉換為 JSON 格式。

什麼是 JSON？

JSON 是一種輕量級的結構化資料格式，使用鍵值對與陣列來組織資料。與 CSV 的平面二維結構不同，JSON 支援巢狀層次，可以表達複雜的資料關係。JSON 已成為 Web API 的事實標準格式，也是 MongoDB 等 NoSQL 資料庫的原生資料格式。

JSON 支援多種資料型別——字串、數字、布林值、陣列、物件、null——這使得它能夠更精確地表達資料的語義，而不像 CSV 那樣所有值都是純文字。

CSV 與 JSON 詳細對比

CSV

  • 平面二維表格，結構簡單
  • 所有值皆為純文字，無型別資訊
  • Excel 與試算表軟體原生支援
  • 人類可直接閱讀與編輯
  • 檔案小、傳輸效率高
  • 無法表達巢狀結構

JSON

  • 支援巢狀結構與複雜資料關係
  • 支援多種資料型別（字串、數字、布林、Null）
  • API 與 NoSQL 資料庫標準格式
  • 程式解析效率高
  • 可讀性佳，適合除錯
  • 物件結構比 CSV 略大

實戰範例：CSV → JSON 完整轉換

CSV 輸入

name,age,active,score,profile.city,profile.department
Alice Chen,30,true,95.5,台北市,Engineering
Bob Wang,35,false,87.0,台中市,Design

JSON 輸出（Nested Object 模式）

[
  {
    "name": "Alice Chen",
    "age": 30,
    "active": true,
    "score": 95.5,
    "profile": {
      "city": "台北市",
      "department": "Engineering"
    }
  },
  {
    "name": "Bob Wang",
    "age": 35,
    "active": false,
    "score": 87,
    "profile": {
      "city": "台中市",
      "department": "Design"
    }
  }
]

自動型別判斷將 "30" 轉為數字 30，"true" 轉為布林 true，巢狀欄位 profile.city 展開為巢狀物件。

CSV to JSON 的應用場景

  • API 資料準備：將 Excel 中的產品清單匯出為 CSV，轉為 JSON 後透過 API 提供給前端應用
  • NoSQL 資料庫匯入：MongoDB 的 mongoimport 支援 JSON 格式，CSV 需要先轉換才能匯入
  • JavaScript / TypeScript 設定：將 CSV 設定檔或翻譯表轉為 JSON 模組，直接在程式碼中 import 使用
  • AI / LLM 訓練資料：許多 AI 模型的訓練資料以 JSON 格式儲存，CSV 需要轉換後才能用於 Fine-tuning
  • 資料遷移：從關聯式資料庫匯出為 CSV，轉為 JSON 後遷移至文件型資料庫
