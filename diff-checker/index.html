常見問題 (FAQ)

Diff 是什麼？
Diff 是 difference（差異）的縮寫，指透過比較兩段文字內容，找出新增、刪除與修改的部分。Diff 工具廣泛應用於程式碼版本控制（如 Git diff）、文件校稿與資料比對。其核心演算法基於最長共同子序列（LCS, Longest Common Subsequence），可精確定位哪些內容被加入、移除或變更。
Line Diff、Word Diff 與 Character Diff 有什麼不同？
Line Diff：以行為單位比較最適合程式碼與結構化文字變更，為最常用的 Diff 模式。

Word Diff：以單詞為單位比較，適合文章校稿與 Prompt 比較，可精確到每個單字的變更。

Character Diff：以字元為單位比較，最精細的比較模式，可顯示每個字元的增減，但對於大量文字可能較難閱讀。

建議：程式碼用 Line Diff，文章用 Word Diff，需要精確找出拼寫變更時用 Character Diff。
JSON Diff 的最佳實踐？
開啟「JSON 模式」後，工具會自動對兩邊的 JSON 進行格式化和排序，然後再比較。這樣可以避免因縮排、鍵值順序不同而產生的誤判。

建議在比較 JSON 時同時開啟「忽略空白」選項，以獲得更乾淨的比較結果。如果 JSON 中有時間戳或 UUID 等動態值，可以先將其正規化再比較。
相似度 (Similarity) 是如何計算的？
相似度使用最長共同子序列（LCS）演算法計算，公式為：

Similarity = (2 × LCS長度) / (左文字長度 + 右文字長度) × 100%

這個指標也稱為 Díce 係數，值越接近 100% 表示兩段文字越相似。一般來說：
• 100%：完全相同
• 80-99%：小幅修改
• 50-79%：大幅修改
• < 50%：大部分不同
如何比較 AI 產生內容？
本工具會自動偵測輸入內容是否為 AI Prompt（系統提示詞、角色設定等），並顯示 Token 估算值與 Prompt 特定統計。比較 AI 產生內容時，建議使用 Word Diff 模式，因為 LLM 輸出通常會在同義詞與句式上出現差異。

常見的使用場景包括：
• 比較不同版本 Prompt 的輸出差異
• 比較 A/B 測試的 LLM 回覆
• 比較微調前後的模型輸出
Diff 在 Git 中是如何運作的？
Git 使用內建的 diff 引擎來追蹤檔案變更。當你執行 git diff 時，Git 會比較工作目錄與暫存區（或兩個 commit 之間）的內容，並以統一格式（Unified Diff）顯示差異。本工具提供了類似但更視覺化的比較體驗，支援同步捲動與色彩標示，適合不熟悉命令列的操作。

拼寫檢查、細微變更
優點：最精確
