❓ 常見問題 FAQ

關於文字大小寫轉換與程式命名慣例的常見疑問

camelCase 是什麼？在哪些地方使用？

camelCase（駝峰式大小寫）是一種將複合詞組拼接的命名慣例，第一個單字首字母小寫，後續每個單字首字母大寫，其餘字母小寫，且不包含任何分隔符號。

範例：helloWorld、userFirstName、getUserData

主要使用場景：

  • JavaScript / TypeScript — 變數、函式名稱（如 myVariable、calculateTotal()）
  • Java — 方法與區域變數（如 toString()、studentName）
  • JSON — 屬性鍵值（雖然也常用 snake_case）
  • C# / PHP — 區域變數與參數
PascalCase 與 camelCase 有什麼不同？

兩者最大的差異在於第一個單字的首字母：

camelCase：首字小寫 → helloWorld

PascalCase：首字大寫 → HelloWorld

PascalCase（又稱 UpperCamelCase）通常用於：

  • 類別名稱 — 如 UserController、DatabaseManager
  • C# / .NET — 類別、方法、屬性皆使用 PascalCase
  • React 元件 — 如 function UserProfile()
  • TypeScript 型別與介面 — 如 interface UserData
  • 列舉 (Enum) — 如 enum Color { Red, Green, Blue }

簡單記憶法：如果第一個字母大寫就是 PascalCase，小寫就是 camelCase。

snake_case 與 kebab-case 的差異是什麼？

兩者都使用分隔符號來連接單字，但使用的符號不同：

snake_case：使用底線 _ → hello_world_example

kebab-case：使用連字號 - → hello-world-example

snake_case 常見於：

  • Python — 變數與函式名稱（官方 PEP 8 推薦）
  • Ruby — 方法與符號名稱
  • 資料庫 — 資料表與欄位名稱（如 user_id、created_at）
  • 環境變數 — 如 DATABASE_URL（常搭配大寫）

kebab-case 常見於：

  • URL 路徑 — 如 /my-blog-post（SEO 友善）
  • HTML/CSS — class 名稱與自訂屬性（如 data-user-id）
  • 檔案名稱 — 如 my-component.tsx
  • npm 套件名稱 — 如 express-validator

⚠️ kebab-case 無法在大多數程式語言的變數名稱中使用（因為減號會被解讀為減法運算子）。

Title Case 與 Sentence case 有什麼不同？

兩種格式用於不同情境，主要差異在於哪些單字需要大寫：

Title Case：每個主要單字首字母大寫 → The Quick Brown Fox Jumps Over the Lazy Dog

Sentence case：僅首字大寫，其餘小寫 → The quick brown fox jumps over the lazy dog

Title Case（標題大小寫）：

  • 每個實詞（名詞、動詞、形容詞、副詞）的首字母大寫
  • 冠詞（a, an, the）、連接詞（and, but, or）和介系詞（in, on, at）通常小寫
  • 用於：文章標題、書籍名稱、新聞頭條、按鈕標籤

Sentence case（句子大小寫）：

  • 僅句子第一個單字首字母大寫，專有名詞保持大寫
  • 用於：一般文章內容、電子郵件、產品描述、UI 提示文字

💡 簡單來說：Title Case 是「每個單字都大寫」，Sentence case 是「只有開頭大寫」。

SCREAMING_SNAKE_CASE 是什麼？什麼時候用？

SCREAMING_SNAKE_CASE（大寫底線式）就是將 snake_case 全部轉為大寫。所有字母大寫，單字間以底線分隔。

範例：MAX_CONNECTIONS、DATABASE_HOST、API_SECRET_KEY

主要使用場景：

  • 常數 (Constants) — 永不改變的值（如 MAX_RETRY_COUNT = 3）
  • 環境變數 — 作業系統與 Docker 的環境變數慣例
  • 列舉值 (Enum) — 部分語言中列舉成員使用大寫底線
  • 巨集 (Macros) — C/C++ 的前處理器巨集
  • 設定檔 Key — 如 NODE_ENV=production

「SCREAMING」這個名稱很形象 — 就像在「大聲喊叫」這些變數名稱，強調它們是特別重要的常數。

Toggle Case 是什麼功能？

Toggle Case（切換大小寫）會反轉每個英文字母的大小寫狀態。大寫字母變成小寫，小寫字母變成大寫。

範例：Hello World → hELLO wORLD

範例：JavaScript → jAVAsCRIPT

這個功能在以下情況很實用：

  • 不小心按到了 Caps Lock 打錯字時快速修正
  • 需要從某個全大寫或全小寫的來源反轉文字
  • 創造特殊風格的文字效果

實際上很少在程式開發中使用，但作為文字處理工具來說是一個經典又方便的即時救星！

為什麼程式命名慣例如此重要？

在軟體開發中，命名慣例 (Naming Conventions) 是撰寫可維護程式碼的基石。無論是變數、函式、類別還是檔案名稱，一致的命名風格能讓團隊成員快速理解程式碼意圖，減少溝通成本與潛在錯誤。

根據研究，開發者花費 70% 的時間在閱讀程式碼，而非撰寫程式碼。良好的命名習慣能極大提升程式碼的可讀性與可維護性。

💡 核心原則：命名應清楚表達用途，而非如何實現。變數名稱如 userList 比 arr 更容易理解，函式名稱如 getUserById() 比 processData() 更具描述性。

常見程式命名慣例總覽

以下是程式開發中最常用的命名慣例及其適用語言：

camelCase（駝峰式）

camelCase 是 JavaScript、TypeScript 與 Java 生態系中最廣泛使用的命名慣例。其名稱來自於大小寫交替的外觀像駱駝的駝峰。第一個單字以小寫開頭，後續單字以大寫開頭，不使用任何分隔符號。

使用情境：

  • JavaScript/TypeScript：變數與函式名稱（const userName = 'John'、function fetchData()）
  • Java：方法與區域變數（public void getUserInfo()）
  • Swift：變數與函式名稱
  • JSON 屬性鍵：雖然 API 可能使用 snake_case，但 JS 前端習慣使用 camelCase

PascalCase（大寫駝峰式）

PascalCase 與 camelCase 類似，但第一個單字也以大寫開頭。在物件導向程式設計中，PascalCase 幾乎是所有語言的類別命名標準。

使用情境：

  • C#：類別、方法、屬性、命名空間皆使用 PascalCase
  • React 元件：function UserProfile()
  • TypeScript：型別、介面、列舉（type UserData、interface IUser）
  • Java：類別名稱（public class UserController）
  • Flutter/Dart：Widget 類別名稱

snake_case（蛇形式）

snake_case 使用底線 _ 分隔單字，所有字母小寫。它在 Python 生態系中佔有主導地位，也是資料庫設計的常見選擇。

使用情境：

  • Python：PEP 8 規範推薦使用 snake_case 命名變數與函式
  • Ruby：方法與符號名稱
  • SQL／資料庫：資料表與欄位（created_at、user_id）
  • Rust：函式與變數名稱
  • PHP：部分框架使用 snake_case（如 CodeIgniter）

SCREAMING_SNAKE_CASE（大寫蛇形式）

這是 snake_case 的「全大寫」版本，主要用於宣告常數與環境變數。

使用情境：

  • 常數宣告：MAX_RETRY_COUNT = 3
  • 環境變數：DATABASE_URL、API_KEY
  • C/C++ 巨集：#define BUFFER_SIZE 1024
  • Docker：Dockerfile 中的 ENV 變數
  • CI/CD：GitHub Actions 環境變數慣例

kebab-case（烤肉串式）

kebab-case 使用連字號 - 分隔單字，所有字母小寫。因為連字號在大多數程式語言中會被解讀為減法運算子，所以kebab-case 極少用於程式碼內部的命名，但其在 Web 開發檔案與 URL 中非常普遍。

使用情境：

  • HTML/CSS：class 名稱（.my-component）、自訂屬性（data-user-id）
  • 檔案與目錄名稱：my-component.tsx、user-profile-page
  • URL Slug：/how-to-install-nodejs（SEO 最佳化）
  • npm 套件名稱：lodash-es、express-validator
  • Vue.js：元件標籤名稱建議使用 kebab-case

如何選擇適合的命名慣例？

選擇命名慣例時，建議遵循以下原則：

  1. 遵循語言生態系慣例 — 每個語言都有其社群公認的規範（如 Python 的 PEP 8、JavaScript 的 Airbnb Style Guide）
  2. 保持專案一致性 — 在同一個專案中使用統一的命名風格，不要混用
  3. 參考框架/函式庫的命名風格 — 使用 React 時跟隨 React 的 camelCase 慣例
  4. 考慮團隊習慣 — 團隊內部的命名慣例優先於個人偏好
  5. 善用格式化工具 — 使用 ESLint、Prettier 等工具自動規範命名與格式

📌 實用建議：初學者建議先掌握 camelCase（變數/函式）與 PascalCase（類別/元件）的區別，這是最常用也最重要的兩個命名慣例。熟悉後再逐步學習 snake_case 與 kebab-case 的應用場景。
